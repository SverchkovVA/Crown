# Защита данных

## Реализовано

- Только SQLCipher, без незашифрованного запасного режима.
- Случайный 32-байтовый ключ базы. Он не вычисляется непосредственно из пароля.
- Argon2id13: 64 MiB и opslimit 3; параметры формата v1 проверяются до запуска KDF.
- Обёртка ключа: XChaCha20-Poly1305 через PyNaCl Aead, с привязкой к UUID книги.
- Независимый случайный ключ восстановления в коде PF1; внутри key.json хранится
  только зашифрованная обёртка, сам код не записывается приложением.
- База, включая имена банков/счетов, зашифрована. В key.json нет финансовых названий.
- Имена/времена и контрольные данные резервной копии находятся внутри шифрования.
- Временные снимки тоже SQLCipher; открытая SQLite на диск не выгружается.
- Соединения: foreign_keys ON, WAL, synchronous FULL, temp_store MEMORY,
  cipher_memory_security ON, trusted_schema OFF.
- Закрытая сессия не позволяет продолжить запись через сохранённый каталог или журнал.
- Проверка истории пересчитывает хеши справочников и финансовых версий, проверяет
  их предшественников, порядок/суммы частей и точное соответствие проводок. Удаление не стирает историю.
- Ошибки интерфейса не выводят SQL, параметры, пароль или финансовые строки.
- Нет телеметрии, HTTP-клиентов и подключения к внешним сервисам.

На POSIX используются права 0700/0600. На Windows конфиденциальность файлов
дополнительно зависит от ACL пользовательского каталога; проверка Windows ACL
пока не выполнена. SQLite/SQLCipher остаётся самостоятельным слоем шифрования.

## Ограничения модели

Python не гарантирует полное обнуление всех копий секретов в памяти. Ключ базы
нужен открытому приложению. Защита от вредоносного кода с правами пользователя
во время работы не гарантируется.

DPAPI/Keystore, смена парольной фразы, автоблокировка и системная политика
резервирования Android ещё не реализованы. Нельзя считать эту основу готовой
защищённой системой для реальных финансов до проверки следующих этапов.

Встроенный тест блокирует Python socket при создании книги, финансовой
операции, копии и восстановлении с проверкой остатков. Это проверка
наших сценариев, а не полный сетевой аудит ОС и всех нативных библиотек.

Источники для решений: SQLCipher https://www.zetetic.net/sqlcipher/,
libsodium https://doc.libsodium.org/secret-key_cryptography/secretstream и
https://doc.libsodium.org/password_hashing. Исходное исследование: 25.10.2026.


## Локальный импорт

CSV/OFX читается по выбранному пользователем пути, до 8 МиБ/2000 строк. Сеть,
ссылки на изображения и внешние сущности не загружаются; DTD/ENTITY запрещены,
размер/глубина/число узлов и поля ограничены. Исходный файл не изменяется,
не копируется в книгу и не включается в отчёты. В зашифрованном аудите остаются
только нормализованные проведённые строки, отпечатки и ссылки на версии;
номер банковского счёта в область дубликатов входит как SHA-256. Имена файлов
и полный OFX с возможными служебными полями не сохраняются в аудите.
Ошибки структуры не раскрывают содержимое файла в диагностическом сообщении.
Данные в UI показываются буквально; подсказки экранируются.
Автономный тест с запрещённым Python socket включает разбор, подтверждение,
копию и восстановление с обнаружением повтора. Это не аудит всех нативных библиотек ОС.


## Открытый экспорт по выбору пользователя

Экспорт не отправляет данные в сеть. Пользователь выбирает состав, просматривает
его и задаёт новое имя файла. Примечания и теги выключены по умолчанию, названия
можно исключить. Выборка не содержит ключей, паролей/PF1 из хранилища, raw-файлов,
путей, реплик или квитанций. Экспорт — обычный незашифрованный CSV/JSON;
место хранения контролирует пользователь. Предлагается локальная папка AppData.
Сохранение в синхронизируемое хранилище может обрабатываться средствами ОС/пользователя,
это не функция отправки Crown.

В CSV текст названий/примечаний защищается от начальных операторов формул;
JSON сохраняет выбранный исходный текст. Снимок привязан к открытой книге,
сохранение внутри её папки/через символическую ссылку назначения запрещено.
Новое имя публикуется без замены. Чужое временное имя при коллизии не удаляется.
Тесты используют только синтетические файлы, сетевой аудит ОС/ACL и реальное
отключение питания этим не заменяются.

## Локальные правила категорий

Тексты и определения правил хранятся внутри SQLCipher и зашифрованной копии.
Сопоставление буквальное (casefold), без regex, обучения и внешнего сервиса.
Пользовательский текст в таблицах отображается буквально, подсказки экранированы.
Правила не изменяют прошлые операции, суммы, проводки и остатки. Ручной выбор
главнее; при конфликте правило не выбирается произвольно. Их определения не
добавляются в открытый экспорт журнала. [Границы](classification-rules-draft.md).


## Прототип локального OCR

Изображение загружается в память по локальному выбору. Загрузчик ограничивает
формат/байты/геометрию, сохраняет исходник без изменений и не передаёт его
EXIF/текстовые поля движку. Tesseract получает нормализованный PNG через stdin,
возвращает TSV в stdout; временная открытая копия изображения/текста не создаётся.
Текст исключён из repr DTO, ошибки не пересказывают stderr или ответ процесса.
Это уменьшает случайное попадание в журнал, но не защищает RAM от кода с правами
пользователя и не гарантирует обнуление Python-объектов.

Движок вызывается без shell/поиска в PATH/загрузок по сети. EXE/DLL/модели
проверяются по явному манифесту; посторонняя соседняя DLL отклоняется.
Окружение не наследует proxy/TESSDATA_PREFIX, каналы и время ограничены.
Процесс не является sandbox; отсутствие внешних OCR API не заменяет сетевой
аудит нативных DLL и ОС. Runtime пока исследовательский, лицензии зависимостей
и чистая Windows не приняты. В опытных окнах данные показываются локально
и существуют до закрытия окна; отдельное финансовое подтверждение dev10
может сохранить выбранные поля/слова в зашифрованной книге 0010.
Тесты/CI используют только вымышленные PNG/TSV. Частная папка проверялась локально
с выводом агрегатов, без публикации содержимого.


При подготовке будущей поставки OCR состав должен выбираться по закреплённому
манифесту и проверенным лицензиям. Локальные отчёты рядом с runtime не являются
его частью и не включаются в дистрибутив. Сейчас каталог содержит 58 закреплённых
файлов и четыре диагностических JSON; обычный EXE runtime не распространяет.

## Сохранённое происхождение OCR — dev10

До финального подтверждения данные остаются в памяти. После него только слова
полей выбранной строки, области, версии/хеши и ручные исправления входят в SQLCipher
и зашифрованную резервную копию. Изображение/путь и весь экран не сохраняются;
примечание операции также может содержать проверенное описание.

JSON ограничен 128 КиБ, имеет строгие типы/ссылки и повторное воспроизведение;
ошибки, включая чрезмерную вложенность, не раскрывают пакет. Нет передачи внешним
сервисам. Хеши обеспечивают согласованность, а не подлинность банковского документа.
Режим остаётся проверочным; это не полный сетевой аудит DLL и не защита от
вредоносного кода в открытой сессии. [Контракт](ocr-confirmation-contract.md).
