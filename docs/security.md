# Защита данных

## Реализовано

- Только SQLCipher, без незашифрованного запасного режима.
- Случайный 32-байтовый ключ базы. Он не вычисляется непосредственно из пароля.
- Argon2id13: 64 MiB и opslimit 3; параметры формата v1 проверяются до запуска KDF.
- Обёртка ключа: XChaCha20-Poly1305 через PyNaCl Aead, с привязкой к UUID книги.
- Независимый случайный ключ восстановления в коде PF1; внутри key.json хранится
  только зашифрованная обёртка, сам код не записывается приложением.
- База, включая имена банков/счетов, зашифрована. В key.json нет финансовых названий.
- Имена/времена и контрольные данные резервной копии находятся внутри шифрования.
- Временные снимки тоже SQLCipher; открытая SQLite на диск не выгружается.
- Соединения: foreign_keys ON, WAL, synchronous FULL, temp_store MEMORY,
  cipher_memory_security ON, trusted_schema OFF.
- Закрытая сессия не позволяет продолжить запись через сохранённый каталог или журнал.
- Проверка истории пересчитывает хеши справочников и финансовых версий, проверяет
  их предшественников и точное соответствие проводок. Удаление не стирает историю.
- Ошибки интерфейса не выводят SQL, параметры, пароль или финансовые строки.
- Нет телеметрии, HTTP-клиентов и подключения к внешним сервисам.

На POSIX используются права 0700/0600. На Windows конфиденциальность файлов
дополнительно зависит от ACL пользовательского каталога; проверка Windows ACL
пока не выполнена. SQLite/SQLCipher остаётся самостоятельным слоем шифрования.

## Ограничения модели

Python не гарантирует полное обнуление всех копий секретов в памяти. Ключ базы
нужен открытому приложению. Защита от вредоносного кода с правами пользователя
во время работы не гарантируется.

DPAPI/Keystore, смена парольной фразы, автоблокировка и системная политика
резервирования Android ещё не реализованы. Нельзя считать эту основу готовой
защищённой системой для реальных финансов до проверки следующих этапов.

Встроенный тест блокирует Python socket при создании книги, финансовой
операции, копии и восстановлении с проверкой остатков. Это проверка
наших сценариев, а не полный сетевой аудит ОС и всех нативных библиотек.

Источники для решений: SQLCipher https://www.zetetic.net/sqlcipher/,
libsodium https://doc.libsodium.org/secret-key_cryptography/secretstream и
https://doc.libsodium.org/password_hashing. Исходное исследование: 25.10.2026.
