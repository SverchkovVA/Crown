# OCR dev51: частичные поля, направление и цветной текст

06.11.2026. Ветка ocr-field-evidence-dev51, основа — dev50 с интерфейсом dev49.
Стек, зависимости, схема 0014 и форматы книги/ключей/копий не менялись.
Исходный код: be460b229b583db9c2ff096dd76caac1cd9ca54a.
[План и границы](ocr-field-evidence-plan.md).

## Поведение

- Если основная сумма не найдена, карточка сохраняет отдельно найденные
  дату, время, валюту и описание. Недостающая сумма блокирует финансовую
  подготовку; баланс из реквизитов суммой операции не становится.
- Единственная явная подпись «Счёт/Карта списания/зачисления» может заполнить
  неизвестное направление. Известный знак главнее подписи. При двух ролях
  направление остаётся неоднозначным. Имя отправителя или получателя и
  предполагаемый характер покупки не определяют движение денег.
  Слова, координаты и низкая оценка подписи сохраняются.
- На преимущественно тёмном фоне цветной текст готовится по самому яркому
  RGB-каналу. Зелёные суммы поступлений перестают бледнеть при переводе в серый.
  Для насыщенного цветного фона сохраняется яркостная обработка; светлые,
  прозрачные и малоконтрастные изображения не получают эту новую проекцию.
  Размеры, исходный PNG и его SHA-256 не меняются.
- Версии: generic-card-v8, generic-history-v6; применённая обработка отмечается
  в OCR-контексте как pixels=dark-v2. Ранее сохранённый аудит не переписывается.
  Защита повторного импорта остаётся прежней.

Существующее предложение списания по длинному тире уже было в приложении
до dev51. Здесь оно не объявляется новой способностью исходного адаптера.
Контроль двух ролей счёта сохраняет неоднозначность и на уровне предложения.

## Воспроизводимое измерение

tools/benchmark_ocr.py принимает только каталог проверенного OCR-модуля,
новый JSON-отчёт и необязательный новый каталог сгенерированных PNG.
Пользовательской выборки, входа произвольных изображений и записи в книгу нет.
Набор tools/ocr_benchmark_samples.py: 12 вымышленных макетов, 40 денежных строк,
светлая/тёмная/смешанная тема, размеры текста 28/34/38 px, четыре карточки,
шесть историй, два отрицательных контроля. Есть часы, итоги дня и бонусная подпись.

В отчёте отдельно считаются предложения и точные поля из OCR-источника.
Год/валюта по настройке не считаются распознанными в источнике.
Сравнение строк идёт по порядку: пропуск не скрывается подбором другой строки.
Даже заблокированная ложная сумма нарушает отрицательный контроль.
Сохраняются SHA-256 синтетических изображений, разрешённый шрифт и версии
движка/моделей. Финансовых значений из пользовательских снимков в отчёте нет.

Windows 11, Qt 6.12.0, Segoe UI, один и тот же закреплённый Tesseract и модели:

| Метрика | dev50 | dev51 |
|---|---:|---:|
| Полностью совпавшие случаи | 8/12 | 11/12 |
| Пропущенные денежные строки | 6 | 0 |
| Лишние денежные строки | 0 | 0 |
| Сумма предложения, точное совпадение | 25/40 | 40/40 |
| Валюта предложения, точное совпадение | 34/40 | 40/40 |
| Направление предложения, точное совпадение | 30/40 | 39/40 |
| Дата предложения, точное совпадение | 31/40 | 40/40 |
| Время предложения, точное совпадение | 4/4 | 4/4 |

Для dev51 точные исходные поля: сумма 40/40, валюта 30/40,
направление 21/40, дата 34/40, время 4/4. Остальные совпадения предложений
включают существующее уточнение тире и настройки валюты/года.
При пропусках dev50 порядок строк сдвигается, поэтому число точных сумм
меньше числа найденных строк. Обе метрики оставлены видимыми.

Один случай dev51 остаётся needs_review: движок теряет знак одной суммы
в истории с крупным текстом. Сумма и дата найдены, направление неизвестно.
Утверждение «вся матрица прошла» неверно; CLI возвращает 1.
Это небольшая измерительная выборка, по которой исправлялась обработка,
а не независимая оценка банковской точности.

Первая проба с отсутствующим шрифтом рисовала квадраты вместо текста и
исключена из измерения. Генератор теперь проверяет нужные символы и отказывает
без пригодного шрифта. Подключение существующего TTF действует только внутри
процесса. Проба утолщения MinFilter(3) и другой режим сегментации ухудшили
полноту; в приложение они не включены.

Повторный запуск из корня этой ветки:
```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
uv run --frozen python -m tools.benchmark_ocr --ocr-runtime <каталог-ocr-runtime> --report artifacts/новое-измерение.json
```
Имена файлов должны быть новыми. Код 1 означает незавершённую проверку макета;
не скрывайте его как успешный результат.

- Целевые исходные контроли полей: до исправления 7 failures / 7 passed;
  после — 205 passed в расширенном наборе.
- Контраст/прежняя нормализация/runtime: 35 passed.
- Финальные контроли метрик, полей и цвета: 26 passed (1.69 с).
- Ruff/форматирование 306 файлов и Mypy 154 исходных файла passed.
- Windows PowerShell 5.1 / PyInstaller / изолированный EXE: passed, 30 шагов.
- Исходники и финальный EXE с настоящим локальным OCR: passed, по 32 шага,
  Qt/windows, приложение 0.2.0.dev51.
- Широкий OCR/generic/tesseract-набор: 768 passed, 1346 deselected,
  353.90 с. Только синтетические книги и изображения.
- [Полный CI dev51](https://github.com/SverchkovVA/Crown/actions/runs/42131722134)
  запущен; результат будет добавлен после завершения.

dev51-ocr-regressions.xml, dev50-benchmark-baseline.json,
