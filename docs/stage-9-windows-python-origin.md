# Происхождение нативных файлов CPython в Windows-поставке

27 файлов управляемого CPython в пакете dev128 побайтово совпали с файлами
официального архива `3.13.16+20261013` для Windows x64. Сверены также
текст лицензии CPython и опубликованный SHA-256 архива
`7aba3985d4cee1c7cacb963ca6aa08a5d3e695d7f9609d9fabc56f22ddcf5a06`.
Полный архив с метаданными и лицензиями сверён по SHA-256
`784db2d7087fbecf1e0b807f908f2846de039e107e4195736039c8a217884b46`.
[Официальная сборка Python Build Standalone](https://github.com/astral-sh/python-build-standalone/releases/tag/20261013)

Метаданные полного архива указывают `libcrypto-1_1-x64` и `libssl-1_1-x64`
в записях про `_ssl` и `_hashlib`. В реальных PE-импортах этого комплекта
указаны `libcrypto-3-x64.dll` и `libssl-3-x64.dll`, а Python сообщает OpenSSL
3.5.9. Для состава поставки использованы измеренные файлы и PE-импорты.
Поле `license_paths` этой сборки ссылается на текст OpenSSL 3.

В dev131 в комплект добавлены точные тексты OpenSSL 3, libffi, bzip2, liblzma
и SQLite из полного архива. Присутствие OpenSSL, libffi и SQLite подтверждают
PE-импорты. Связь bzip2 и liblzma с упакованными `_bz2` и `_lzma`
зафиксирована в метаданных сборки. Пять новых файлов входят в ту же ведомость
SHA-256, что и ранее добавленные тексты основы.
[Ведомость Windows](legal/windows-foundation/manifest.json)

Дополнительно нужно уточнить условия распространения Microsoft Runtime,
уведомления для остальных встроенных компонентов CPython, точные зависимости
Qt и OCR. Проверка архивных SHA-256 устанавливает соответствие байтов
опубликованным файлам, а проверка применимых лицензий ведётся отдельно.
