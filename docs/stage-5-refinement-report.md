## Что изменено

1. В карточках Т-Банка значок навигации мог попасть в ту же OCR-строку, что дата.
   Разбор теперь допускает известный знак только в начале целой даты. Слова,
   индексы, оценки и области исходника сохраняются. Поиска даты внутри произвольного
   текста нет; лишние хвосты, вторая/относительная дата и неверный календарь не принимаются.
   Год без указания по-прежнему предлагает настройка, raw-поле не меняется.
2. MainWindow передаёт снимок существующих правил категорий в таблицу OCR.
   Используется прежний буквальный доменный движок с видом/счётом/приоритетом,
   без новых финансовых команд, сети и обучения. Флажок подсказок действует в окне.
3. Автоматическая категория пересчитывается при изменении счёта/вида/описания.
   Ручной выбор, включая повторный выбор той же категории, главнее и сохраняется
   при выключении/включении подсказок. Свои переводы/исключения не становятся
   доходом/расходом из-за правил. Уже записанные строки и прошлые факты не меняются.
4. При включённых подсказках конфликт равного приоритета разных категорий требует
   ручного выбора. Ничего не записывается частично. Причина и номер первой ошибочной
   строки показаны над таблицей, остальные правки остаются в окне.

Это выполнение пункта подсказок в [плане этапа 5](stage-5-plan.md), а не новый
механизм категоризации. Подсказки пока только в списке: одиночная финансовая форма
OCR остаётся с ручной категорией. Подсказка не является отдельным фактом аудита
правила: финансовый журнал хранит выбранную категорию, определения правил имеют
прежнюю историю версий. Формат аудита v1, деньги, ключи, копия, миграции и состав
зависимостей не менялись; в uv.lock изменена только версия самого проекта.

передачи распознанного текста/сумм/имён/путей в чат/Git/CI. Исходные SHA-256
до/после совпали. Отчёт содержит только агрегаты:
artifacts/ocr-dev12-private-aggregate.json; его source_sha256 совпадает с кодом выше.

У Т-Банка два из четырёх поддержанных отдельных макетов теперь имеют полные
предложения обязательных полей вместо нуля в dev11. В одном всё ещё не выделена
сумма; остальные неизвестные поля остаются для ручной правки. Истории дают прежние
5/6/5 строк, все 16 с предложением даты. У ВТБ — две полные карточки и четыре
строки истории с датами. Это не ручная разметка точности и не утверждение, что
предложенные финансовые значения совпадают с оригиналами каждого снимка.

## Ручная проверка и оставшиеся ограничения

Подготовлены artifacts/manual-ocr-dev12/start.cmd, six-operations.png,
fictional-card-date.png и ПРОВЕРКА.txt. Секреты/готовая книга отсутствуют:
для ручного запуска нужна новая тестовая книга либо восстановленная в новую папку
копия 0011 и собственный пароль пользователя. Старые launcher из artifacts запускают
текущие исходники, имя папки старой инструкции не закрепляет исполняемую версию.

Новых реальных данных сейчас не требуется. Полезно проверить удобство подсказок,
ручную категорию, конфликт и дату карточки; запись/копия/повторы проверены автоматически.
Обычный EXE без OCR-runtime/меню; launcher зависит от .venv, исходников и локального
runtime. RUB только. Два отдельных макета Т-Банка остаются неполными; Яндекс Пэй,
контрольный набор точности, сохранённые черновики, просмотр аудита, визуальное
сопоставление снимков, лицензии/поставка runtime и чистая Windows ещё впереди.
Этап 5 не объявляется завершённым.
