# Сборка и проверка Windows

Целевая ОС: Windows 11 x64. Python: 3.13.16. Зависимости и хеши — uv.lock.
Первый пользовательский прогон подтвердил установку и импорт sqlcipher3 для
Windows. Приёмка основы указана в docs/stage-3-report.md; первая поставка
журнала — docs/stage-4-report.md; разделение — docs/stage-4-split-report.md; возвраты — docs/stage-4-refund-report.md; закрытые месяцы — docs/stage-4-period-report.md; сверка — docs/stage-4-reconciliation-report.md; теги/фильтры — docs/stage-4-organization-report.md; импорт — docs/stage-4-import-report.md; экспорт — docs/stage-4-export-report.md; основа 0.2.0.dev9
с правилами — docs/stage-4-classification-report.md; текущая опытная dev15
с первым отчётом — docs/stage-6-analytics-report.md.

PyInstaller spec включает миграции Alembic как ресурсы и необходимые динамические
импорты. Используется каталог приложения, без onefile, UPX и Qt WebEngine.

Полный прогон: check-windows.cmd или packaging/windows/verify.ps1. Отдельная
сборка: packaging/windows/build.ps1. Скрипты сохраняются с UTF-8 BOM для Windows
PowerShell 5.1; первый Windows-прогон выявил ошибку обработки JSON-массива
в тесте помощников. Исправление, полный прогон и самопроверка EXE подтверждены
Windows CI #3; подробности и ссылка — в docs/stage-3-report.md.

Дочерние программы запускаются без оболочки, с раздельным асинхронным чтением
вывода, проверкой exit code и ограничением времени. Для .NET Framework используется
экранирование аргументов Windows. Проверка соответствующих помощников запускается
до основных этапов. Существующие папки сборок не заменяются.

PyInstaller запускается напрямую через Python из `.venv`. Только для процесса
сборщика PATH ограничен каталогом этого Python и системными каталогами Windows;
PYTHONPATH/PYTHONHOME убраны. Это исключает подбор старых системных DLL из
посторонних программ в пользовательском PATH. Постоянные переменные Windows
не меняются. Самопроверка готового EXE выполняется с обычным унаследованным PATH,
чтобы проверить запуск в исходном окружении.

CI checks.yml описывает Linux-проверки и полный прогон Windows под PowerShell 5.1.
Headless-прогон CI отдельно отмечается в JSON. Прогоны доступны в
[SverchkovVA/Crown Actions](https://github.com/SverchkovVA/Crown/actions).
После каждого Windows-прогона CI сохраняет артефакт windows-check с отчётами
и журналами только синтетических тестов; срок хранения — 14 дней.
Успех headless CI не заменяет ручную приёмку на Windows 11.

## Приёмка Windows 11

- Установка зависимостей по lock-файлу, lint/type/test и --self-test.
- Сборка каталога, повторная самопроверка уже собранного EXE.
- Перенос каталога на чистую Windows без Python/uv.
- Открытие обычным пользователем; кириллица и пробелы в пути.
- Книга → счёт → копия → закрытие → восстановление с новым паролем.
- Отсутствие сети, неправильный пароль, недоступная папка и нехватка места.
- Масштабирование 100/125/150%, клавиатурная навигация и многомониторный режим.
- Проверка DLL, зависимостей Visual C++, ACL и завершения процесса во время записи.

На этапе 3 ещё не создаётся финальный NSIS-установщик; нет цифровой подписи,
системы обновлений и проверки лицензий готового публичного дистрибутива.
Эти результаты относятся к завершению Windows на этапе 9.

Предыдущая dev13 создаёт 0011 и включает 20 шагов самопроверки. SVG-индикаторы из
presentation/icons включены в данные PyInstaller и проверяются чтением Qt в EXE.
Бюджет полного набора 30 минут, job CI — 40, диагностика теста 90 с.
Обычный EXE остаётся без OCR-runtime/меню; параметры/свои отправители и прежний
журнал доступны, опытное распознавание запускается из исходников.
Самопроверка preview_ocr_without_engine также создаёт общий список без финансового
сервиса и проверяет результат в памяти/отсутствие Job записи. Это включает новые
парсеры в сборку, но не добавляет в неё OCR-runtime или меню.
[Текущий отчёт](stage-5-universal-report.md).

## Dev14: отчёт и 21 шаг

Новый read-only отчёт включается в обычный каталог EXE; OCR-runtime/меню там
по-прежнему отсутствуют. Схема 0011 прежняя; миграция 0012 только подготовлена,
не достигается штатным созданием/восстановлением. Самопроверки имеют 21 шаг,
новый проверяет точную сумму отчёта и его совпадение после восстановления.
[Текущие результаты](stage-6-analytics-report.md).

## Dev15: детализация без изменения схемы

Из отчёта доступны исходные версии, полная сумма и вклад в отбор. Зависимости,
схема 0011 и 21 шаг самопроверки сохранены. Обычный EXE без OCR-runtime/меню.
