# Начало подготовки установщика Windows

В портативной сборке достаточно распаковать каталог, но Windows не добавляет
его в меню «Пуск» и список установленных программ. Установка поверх предыдущей
версии заняла бы меньше места, но потребовала бы восстановления прежних файлов
после сбоя. Для первого установщика Crown предусмотрен отдельный каталог
версии в профиле Windows. Так можно проверить установку и удаление рядом с
другими версиями приложения.

## Порядок реализации

1. Сборщик PyInstaller записывает SHA-256 и размер каждого файла приложения.
   Каталог для установщика содержит EXE и зависимые файлы `_internal`.
2. NSIS устанавливает программу для текущего пользователя. Целевая папка
   версии должна быть свободна. Ярлык и регистрация приложения появляются
   после подготовки каталога. Нужны русские сообщения об ошибках установки.
3. Удаление использует перечень файлов именно этой версии. Книги, копии,
   настройки и файлы, которых нет в перечне, сохраняются.
4. В чистой Windows без сети и Python проверяются установка, повторный запуск
   установщика, авария, удаление и сохранность отдельной учебной книги.
   Установленный EXE сравнивается с исходной ведомостью целиком.

Первый образ содержит обычную поставку PyInstaller. Отдельный комплект OCR,
подпись выпуска и обновления остаются самостоятельными задачами. В проверках
используются только искусственные данные. Чтение поддерживаемых схем 0002–0018
проверяется без миграции исходной базы.

[Справочник NSIS](https://nsis.sourceforge.io/Docs/Chapter4.html)


В dev124 штатный сборщик Windows записывает `app-payload.json` и его SHA-256
в `build-result.json`. На Windows PowerShell 5.1 проверено 1132 файла,
178736409 байт. Девять связанных тестов прошли. Ruff и Mypy прошли.
