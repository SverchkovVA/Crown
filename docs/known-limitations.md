# Известные ограничения

1. Проверочная версия, не для реальных финансов. Полная приёмка Windows 11 ещё не завершена.
2. В 0.2.0.dev8 есть ручной журнал, начальные остатки, остатки на дату,
   разделение, возвраты, закрытие месяцев, сверка, теги, сохранённые фильтры,
   ограниченный CSV/OFX-импорт и управляемый экспорт журнала. Финансовых отчётов нет. Полный этап 4 ещё не принят.
3. Нет редактирования/архивирования счетов и категорий. Созданные записи сохраняются.
4. Нет OCR, вкладов, аналитики, планов и инвестиций. Экспорт пока охватывает
   журнал; отдельные наборы справочников, прочие модули и пакет ChatGPT — этап 8.
5. Резервирование ручное. Нет расписания, ротации, автоблокировки и смены пароля.
6. Восстановление только в новую папку, без замены текущих данных. Поддерживаются
   схемы 0002/0003/0004/0005/0006/0007/0008; копия 0002/0003/0004/0005/0006/0007 обновляется до 0008 при восстановлении. Размер базы
   ограничен 10 GiB. Понижение версии схемы не поддерживается.
7. Исходные старые книги не мигрируются при открытии. Для журнала из 0002
   или разделения из 0003, возвратов из 0004, закрытия периодов из 0005, тегов/сохранённых фильтров из 0006, импорта из 0007 нужен переход через копию и восстановление в новую папку. Неизвестная схема
   отклоняется. Не смешивайте восстановленную и исходную книгу при ручной работе.
8. Нет синхронизации. Таблицы версий и журнала не означают готовый сетевой протокол.
9. Нет DPAPI, аппаратного хранилища Android и гарантированного обнуления Python RAM.
10. Модель защищает закрытые файлы, но не открытое приложение от вредоносного кода
    с правами пользователя.
11. Полный сетевой аудит и реальные отключения питания не проводились. Тест
    завершения процесса покрывает другой класс аварий.
12. Нет NSIS-установщика, подписи и проверки полного лицензирования дистрибутива.
13. Проект опубликован в SverchkovVA/Crown. Результаты фактических прогонов CI
    и оставшиеся проверки приведены в docs/stage-3-report.md.
14. Сценарий Windows и отчёты добавлены в 0.1.1. Проверка их помощников в
    PowerShell на Linux не означает работоспособность приложения на Windows.

15. В одном ручном сценарии PF1 не включил режим автоматически, но открыл книгу
    после ручного включения флажка. Синтетические проверки клавиатурного ввода
    и вставки проходят; причина ручного результата ещё не установлена.

16. Возвраты связаны только с расходом, включая его части; отдельного возврата
    комиссии перевода и автоматического подбора покупки нет. Пересчёт остатка
    выполняется при чтении журнала; нагрузка на большой журнал ещё не измерена.

17. Закрытие действует на календарный месяц всей книги. Произвольные диапазоны,
    автоматическое закрытие и контроль входящих сетевых изменений не реализованы.

18. Сверка — разовое сравнение с введённым остатком, в UI только RUB. История
    сверок и отметки отдельных строк не сохраняются. CSV/OFX-импорт — отдельный
    сценарий, без автоматического сопоставления полной выписки с контрольным
    остатком; сумму для сверки пользователь вводит самостоятельно.

19. Теги и сохранённые фильтры переносимы через копию, но сетевой синхронизации
    ещё нет. Фильтр показывает целую операцию, включая перевод и его комиссию;
    это не отдельный аналитический расчёт по части выбранных категорий.

20. CSV требует заголовок и столбец суммы со знаком, UTF-8/Windows-1251,
    даты ДД.ММ.ГГГГ либо ГГГГ-ММ-ДД. Раздельные колонки прихода/расхода
    и специфические банковские макеты ещё не поддерживаются. OFX — ограниченные
    1.x SGML/2.x XML, один счёт, проведённые RUB-строки; банковские корректировки
    и дополнительные валюты исключаются с видимой ошибкой, ожидающие не импортируются.
    Размер до 8 МиБ, до 2000 строк. Ошибочные строки исправляются в исходном файле
    либо исключаются. Нет фонового подключения к банкам. Подготовлено ядро правил
    категорий (docs/classification-rules-draft.md), без SQL/GUI и подключения к импорту.
    Без внешнего ID точный повтор гарантирован только для того же файла/номера;
    совпадение даты/суммы в иной выгрузке требует ручного решения. Форматы Т-Банка,
    ВТБ и Яндекс Пэй на пользовательских выгрузках ещё не приняты.

21. Экспорт — открытый файл выбранных текущих версий, без полной истории книги.
    Удалённые операции включаются явно. Предпросмотр показывает до 200 строк,
    сохранение — всю выборку. JSON хранит минимальные единицы десятичными строками;
    CSV имеет русские заголовки и читаемые суммы, но тип ячейки в сторонней таблице
    задаёт её программа. Для точности больших чисел импортируйте столбцы как текст.
    Формат журнала не предназначен для обратного CSV/OFX-импорта и распознаётся
    как неподдерживаемый банковский файл. Перенос всей книги — через копию.

Эти ограничения не снимают обязательства конечного плана.
