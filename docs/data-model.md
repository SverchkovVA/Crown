# Модель данных: схема 0006 (чтение 0002/0003/0004/0005)

SQLAlchemy используется через Core для небольшого адаптера неизменяемых записей.
Это тот же утверждённый SQLAlchemy; ORM-модели не дублируют доменные сущности.
Alembic поставляется внутри Python-пакета, чтобы миграции были доступны в сборке.

## Таблицы

| Таблица | Содержимое |
|---|---|
| currencies | Код валюты и число дробных знаков; сейчас RUB, 2 |
| books | UUID книги, название, валюта и время создания UTC |
| replicas | UUID реплики и последовательность её изменений |
| local_state | Единственная текущая локальная реплика |
| entities | UUID, книга, тип и принятая версия |
| entity_revisions | UUID версии, автор, последовательность, группа, время, хеш, флаги |
| revision_parents | Предшествующие версии; для будущих изменений и конфликтов |
| revision_heads | Последние ветви сущности |
| change_groups | Группы атомарных изменений |
| change_log | Запись о каждом созданном изменении |
| command_receipts | Идентификатор команды, хеш запроса и сохранённый результат |
| institution_revisions | Название банка/организации |
| account_revisions | Название, тип, банк, валюта |
| category_revisions | Название, доход/расход, родитель |
| ledger_accounts | Внутренние счета активов, доходов, расходов и начального капитала |
| operation_revisions | Вид, дата, счета, сумма, категория, комиссия, примечание; для возврата UUID расхода и его версии |
| postings | Точные подписанные суммы по внутренним счетам и версии операции |
| operation_parts | Порядок, категория и положительная сумма части дохода/расхода/возврата |
| period_revisions | Месяц ГГГГ-ММ, признак закрытия и причина; общая версия kind=period |

Таблицы приложения — STRICT. Ключи и связи обязательны; состояние проверяется
не только интерфейсом. Версия собирается в транзакции, затем запечатывается.
Триггеры запрещают изменение/удаление запечатанной версии и её типизированной
части. Принятая версия должна принадлежать сущности и быть завершённой.

Начальные справочники: Т-Банк, ВТБ, Яндекс Пэй; восемь категорий. Это локальные
названия, без подключения к банкам. Добавление собственного банка поддерживается.

Типы счетов: банковский, накопительный, наличные, инвестиционный. Тип
«инвестиционный» пока обозначает только счёт: учёта бумаг ещё нет.

## Деньги

`Money.minor` — целое в пределах ±(2^63−1). RUB хранится в копейках. Ввод не
округляет лишние дробные знаки, не принимает NaN/Infinity и не смешивает валюты.
Большие положительные/отрицательные показатели степени не превращаются в ноль
или переполнение. Currency проверяет код и точность.

Схема 0003 содержит финансовую дату без времени, внутренние счета, операции
и проводки. Сумма проводок равна нулю по каждой валюте. Приход увеличивает
актив и кредитует доход; расход уменьшает актив и дебетует расход. Перевод
уменьшает исходный актив на сумму плюс комиссию, увеличивает целевой на сумму
и относит комиссию в расходы. Начальный остаток связан со счётом капитала.
Идентификаторы внутренних счетов детерминированы UUID5 по книге/роли/ссылке/валюте.

Остатки используют только принятые неудалённые версии. Исправление создаёт новую
версию с parent; удаление сохраняет типизированный payload и проводки в истории,
но исключает их эффект из баланса. Хеш включает содержимое, признак удаления и
предшественника. История строится по цепочке родителей, а не времени устройства.

## Разделение операции

Версия дохода/расхода/возврата содержит либо одну category_id, либо 2–100 частей без
общей категории. Части неизменяемы, категории не повторяются; валюта каждой
части равна валюте операции, суммы положительны и в сумме точно равны общей.
Счёт актива изменяется один раз на общую сумму. Комиссия перевода остаётся
отдельной расходной проводкой; перевод и начальный остаток не разделяются.

Части включены в хеш и квитанцию команды в сохранённом порядке. Для обычных
операций ключ parts отсутствует в сериализации, поэтому опубликованные хеши
и квитанции 0003 сохраняются. Старые версии не переписываются при миграции.
Контроль целостности проверяет также непрерывный порядок частей и проводки.

## Связанные возвраты

`refund_of` ссылается на сущность расхода, `refund_of_revision_id` — на
запечатанную версию этого расхода той же книги. Оба поля обязательны только
для REFUND. Источник должен быть неудалённым расходом; валюта совпадает, дата
возврата не предшествует покупке. Получатель может быть другим счётом той же валюты.

Возврат увеличивает актив и кредитует расходные категории; доход не возникает.
Каждая категория берётся из источника. Сумма всех действующих возвратов
ограничена текущей суммой покупки по каждой категории. Удаление возврата
освобождает эту сумму; несовместимая правка/удаление покупки отклоняется целиком.
Старый снимок источника остаётся в истории, новые/исправленные возвраты должны
ссылаться на текущую принятую версию покупки.

Ссылки входят в payload/хеш/квитанцию только для возврата; пустые ключи
не добавляются к обычным операциям и частям схем 0003/0004. Триггеры контролируют
типизированные ссылки при запечатывании, адаптер — совокупные ограничения
в одной транзакции. Проверка целостности проверяет историю и активное состояние.

## Закрытие месяцев

Период охватывает календарный месяц всей книги. UUID сущности детерминирован
по UUID книги и месяцу, поэтому один месяц имеет одну линейную историю.
Первая версия закрывает месяц, последующие чередуют открытие/закрытие.
Открытие требует причины; повторное закрытие использует ожидаемую открытую
версию. Причина, состояние и предшественник входят в хеш. Финансовые payload,
проводки и старые хеши не меняются из-за закрытия.

Добавление операции проверяет новый месяц; исправление/удаление — также
месяц прежней принятой версии. Перенос даты не обходит запрет. Проверка
происходит после проверки повтора команды: повтор уже выполненного запроса
возвращает старый результат, не записывая новую версию. SQL-триггер дублирует
запрет при запечатывании. Возврат закрытой покупки допустим в более позднем
открытом месяце, поскольку исходную покупку он не меняет.

## Миграции

0001: книга, реплики, версии, журнал и повторяемые команды.
0002: банки, счета, категории и защита их версий.

0003: внутренние счета, финансовые версии, проводки и проверка запечатывания.

0004: части доходов/расходов, проверка суммы и неизменяемости.

0005: связанные возвраты и снимок источника, защита ссылок и частей возврата.

0006: версии закрытия месяцев, защита переходов и финансовых правок.

Новая пустая база получает 0006. Открытие поддерживает 0002/0003/0004/0005/0006 без миграции
исходной книги; неизвестная схема отклоняется. Понижение запрещено. Восстановление
копии 0002/0003/0004/0005 обновляет только промежуточную базу до 0006, проверяет внешние ключи,
полную целостность, создаёт новую реплику/пароль/код и публикует новую папку.
Сбой миграции не публикует книгу. Исходная книга и контейнер копии сохраняются.
В 0.1.1 и 0.1.2 схема 0002 одинакова; формат ключей и контейнер v1 не изменены.
