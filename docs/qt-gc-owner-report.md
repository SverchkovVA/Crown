## Решение и границы

Python может начать автоматическую сборку циклов в рабочем потоке.
Обёртка Qt при этом может освободить принадлежащий Python объект C++.
[Документация Shiboken](https://doc.qt.io/qtforpython-6/shiboken2/typesystem_ownership.html)
описывает владение и освобождение обёрток, а
[правила Qt](https://doc.qt.io/qtforpython-6/overviews/qtdoc-threads-qobject.html)
требуют учитывать поток объекта.
[Python3.13](https://docs.python.org/3.13/library/gc.html)
разделяет подсчёт ссылок, автоматическую сборку циклов и явный collect.

Перед первой фоновой задачей приложение назначает владельца циклической
сборки — QObject с родителем QCoreApplication. Автоматическая сборка циклов
заменяется явной сборкой в GUI: перед запуском задачи и таймером раз в5 секунд.
Подсчёт ссылок Python продолжает работать обычно.
При aboutToQuit восстанавливается прежнее состояние автоматической сборки.
Вложенный collect предотвращён; вызов владельца из рабочего потока отклоняется.
Это политика приложения, а не подмена gc.collect в тестах или отключение проверок.

Точная повреждённая C++-обёртка в аварийном дампе не установлена.
Изменение устраняет наблюдаемый небезопасный путь автоматической сборки в worker;
оно не объявляется универсальным исправлением всех возможных ошибок Qt.
При больших объёмах GUI-объектов потребуется отдельно измерять паузу полной
сборки и длительный расход памяти. Пока данные только синтетические.
