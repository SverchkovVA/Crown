# Надёжность и длительность CI: проект группировки тестов

30.10.2026. Подготовка в artifacts, рабочий workflow пока прежний.
Причина — два фактических тайм-аута полного набора: PR Windows dev30
и PR Linux dev31. Повтор Windows dev30 успешен; повтор Linux dev31 ещё идёт.
Это не зарегистрированные падения assertion. Для dev31 41 совпадающая проверка
периодов/сверки имела медиану интервала между завершениями 3,121 с в успешном
push Linux и 4,626 с в остановленной PR-попытке. Это указывает на замедление
выполнения; точная причина загрузки GitHub runner не установлена.

## Предлагаемый срез

Два независимых Linux-задания без новых Python-зависимостей. Каждое собирает
полный набор, выполняет свою группу и сохраняет JUnit/манифест. Отдельное
задание обязательно проверяет, что выборки не пересекаются и вместе покрывают
всю общую коллекцию, а число успешных JUnit-случаев совпадает с выборкой.
Пропуски выполнения, ошибки, повторные случаи и незавершённые отчёты не принимаются.
Fail-fast отключён, чтобы результат второй группы сохранялся после сбоя первой.

Windows-прогон, ограничения времени, самопроверки, KDF, шифрование и восстановление
не ослабляются. Параллельные задания CI не являются агентами разработки.
Рабочие книги и банковские снимки не используются.

Разделение по полному nodeid оказалось неверным для двух параметров со случайными
UUID, создаваемыми при коллекции. Кандидат группирует всю функцию/семейство вместе;
стабильный ключ случая включает исходное имя и индексы параметров. Независимые
коллекции с разными UUID проверены на полное покрытие без пересечений.
Порядок параметров не используется для назначения функции в группу.

## Получение отчётов при повторе

Проект скачивает каждый отчёт по точному имени linux-tests-0/1 в отдельную папку.
Официальный download-artifact v5 закреплён на
[634f93cb2916e3fdff6788551b99b062d0335ce0](https://github.com/actions/download-artifact/commit/634f93cb2916e3fdff6788551b99b062d0335ce0).
Действие выбирает новейший ID при нескольких одноимённых артефактах; успешная
прежняя группа остаётся доступной при повторе только неуспешного задания.
Стандартное ограничение needs не позволяет объединить результат как успешный,
пока матрица неуспешна.

Большой dist не вернулся содержимым через API-инструмент, поэтому он прочитан
напрямую по закреплённой raw-ссылке, без исполнения. Git blob SHA-1 совпал
с метаданными API: f9d5a305f01e9ee85a9a60ba198ff879d38cc17d, 4 798 779 байт.
В закреплённом исходнике подтверждён выбор максимального databaseId/id.
Проверка относится именно к этому закреплённому действию; это не полный аудит
всего стороннего кода.
