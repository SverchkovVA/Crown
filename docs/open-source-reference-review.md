# Референсы и направление Crown — 06.11.2026

## Вывод

Сохраняем Python 3.13, PySide6 Widgets, SQLAlchemy/Alembic, SQLCipher,
целые минимальные единицы денег и Decimal для ставок. Архитектура — модульный
монолит с отдельными domain/application/infrastructure/presentation.
Замена стека не устраняет обнаруженные ошибки разметки и распознавания;
она потребует повторной проверки криптографии, журнала и поставки.

Это инженерный вывод по требованиям Crown и первичным источникам ниже.
Сравнивались документация, исходная структура и метаданные сопровождения;
приложения не устанавливались, производительность и удобство не измерялись.
Даты актуальны на момент проверки 06.11.2026; свежий push сам по себе
не гарантирует качество или будущую поддержку.

## Какие решения применять

- KMyMoney/MMEX: плотный журнал с явными счётом и категорией, понятная сверка,
  небольшие самостоятельные формы. В Crown — использовать доступную ширину
  таблицы, сохранять заголовки и единицы, не превращать каждую строку в карточку.
- Actual: независимое ядро и длительные операции вне GUI. В Crown это уже
  обеспечивают слои и Job; перенос React/Electron для этого не нужен.
  Сервер синхронизации Actual не заменяет будущий согласованный LAN-протокол.
- Firefly III: разделять правила категоризации, импорт и журнал. В Crown
  правила предлагают значение, ручное решение остаётся главным; повторная
  загрузка не создаёт новое движение без проверки.
- GnuCash: сохранять инварианты проводок независимо от вида экрана. Не добавлять
  весь бухгалтерский интерфейс малого бизнеса к личным финансам.
- Portfolio Performance: разбор исходника → предпросмотр → проверка → запись.
  Наличие распознанного текста ещё не доказывает верную денежную операцию.
  Инвестиционные инструменты и денежные счета развивать отдельными сущностями.
- Maybe: ясная иерархия и спокойная плотность могут быть визуальным ориентиром.
  Популярность интерфейса не означает действующее сопровождение.

Избегать переноса обязательного сервера, Docker, браузерного хранения вместо
шифрованной книги, внешнего OCR, телеметрии и автоматического обновления котировок.
Не переносить произвольный SQL в пользовательский интерфейс Crown ради отчётов.
Не делать новый плагинный фреймворк или микросервисы до реальной необходимости.

## Стек и архитектура

| Вариант | Оценка для требований Crown | Решение |
|---|---|---|
| Текущий Python/PySide6/SQLCipher | Локальный Windows GUI, проверенные точные суммы и шифрование; UI можно исправлять штатными layouts/моделями Qt. | Оставить. |
| TypeScript/React/Electron или Tauri | Полезен при общей веб-версии, которой сейчас нет в согласованном объёме; потребует новой UI/поставки и связывания ядра. | Переписывание сейчас не обосновано. |
| C++/Qt, C#/WinUI или Java/RCP | Возможны, но обнаруженные дефекты не показывают предела Python/Qt. Возрастает цена переноса проверенного ядра. | Не менять язык и GUI. |
| Серверная архитектура | Не отвечает автономности Windows и будущей прямой LAN-синхронизации. | Не вводить обязательный сервер. |

Сохранить внешние порты OCR и хранения, неизменяемые версии и аудит.
Для растущих таблиц рассматривать QAbstractTableModel/delegate при измеренной
проблеме объёма; текущая жалоба на ширину решается ограниченными размерами
колонок и контролируемым заполнением, без переписывания финансового слоя.
Не менять криптоформат и схему 0014 для визуальных правок.

2. Завершить UI: тематическая нативная рамка Windows, навигация над левой
   панелью и название справа, убрать дублирующую «Закрыть» во встроенных формах;
   постоянные действия пакета, ширина таблицы и горизонтальное колесо.
3. Пройти изменённые GUI-сценарии, нативные визуальные проверки, общий набор,
   source/EXE-самопроверки и CI; сохранить самостоятельную контрольную точку.
4. Затем OCR: исключить статусные часы из денежных строк, воспроизвести
   различия файла и вставки на синтетике и проверить pipeline загрузки/контраст.
   Сохранять исходные свидетельства и уточнение неоднозначных сумм.
5. До расширения последующих функций иметь размеченные синтетические проверки
   полноты: пропуски и ложные операции, точные сумма/валюта/знак/дата отдельно.
   Ручные Windows/банковские проверки не засчитывать автоматически.

Порядок уточняет текущую работу, не отменяя дорожную карту и открытые пункты
приёмки. Следующие большие изменения стека/архитектуры остаются отдельным
согласованием; необходимость такого изменения сейчас не обнаружена.
