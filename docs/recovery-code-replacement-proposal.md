# Замена утраченного кода PF1

Проект сценария. В текущих версиях способ открытия книги по существующему
PF1 сохранён. Действующий код можно проверить, открыв книгу с ним. Утраченный
код нельзя прочитать из ключевого файла. В нём находится зашифрованная
обёртка ключа базы, а сам PF1 генерируется случайно и в книгу не записывается.

## Предлагаемый сценарий

1. Пользователь открывает книгу и в разделе «Защита и копии» выбирает «Заменить
   код восстановления». Приложение показывает последствие: прежний PF1
   перестанет открывать книгу с текущим ключевым файлом.
2. Приложение генерирует новый PF1 и показывает его внутри формы. Пользователь
   сохраняет код отдельно. До подтверждения текущий ключевой файл действует.
3. При подтверждении пользователь вводит действующую парольную фразу.
   Приложение сверяет ключ и идентификатор открытой книги, готовит новую
   обёртку PF1 и публикует её под блокировкой книги. Сохраняются парольная
   обёртка, ключ базы, версия формата и данные.
4. После подтверждения форма очищает ввод и скрывает код. Проверить его
   можно обычным открытием книги по PF1.

При отмене или ошибке до публикации действует прежний ключевой файл.
Резервная копия по-прежнему восстанавливается своим паролем в новую папку.
Отдельно сохранённая копия старого ключевого файла сохраняет прежний способ
доступа к ключу базы. Полная смена ключа базы является отдельной задачей.

Если утрачены парольная фраза и PF1, восстановление возможно из ранее
созданной копии с известной фразой архива. Другого способа открыть текущую
книгу в этой модели нет.

## Проверки для реализации

- Прежний PF1 действует до подтверждения. Отказ от действия оставляет
  ключевой файл побайтно прежним.
- Успешное подтверждение принимает прежнюю парольную фразу и новый PF1,
  отклоняет старый PF1 и сохраняет идентификаторы, байты базы и схему.
- Прерывание процесса до и после публикации, отказ в доступе, запись нового
  файла и очистка полей проверяются на временных книгах.
- Проверяются действующие книги поддерживаемых схем, ранее созданная копия,
  наследуемые и защищённые правила доступа NTFS, источник, EXE и чистая Windows.
