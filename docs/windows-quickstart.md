# Проверка на Windows 11

Инструкция сохраняет приёмку 0.1.2 и добавляет проверку журнала с разделением
0.2.0.dev18 в ветке stage-5-ocr; основа stage-4-ledger остаётся dev9.
Для проверки используйте синтетические данные.

## Готовая проверочная сборка из CI

[Проверочная сборка 0.1.2](https://github.com/SverchkovVA/Crown/actions/runs/40359183599/artifacts/12667703301)
прошла 62 Windows-теста и самопроверку EXE. В последующих успешных прогонах
[GitHub Actions](https://github.com/SverchkovVA/Crown/actions) артефакт
`Crown-Windows-x64` также содержит полный каталог программы. Распакуйте его
целиком в новую папку и запустите `PersonalFinance.exe`; соседние файлы и
`_internal` должны оставаться рядом. Для запуска этого каталога Python и uv
не нужны. Это предварительная сборка этапа 3, без установщика.
Артефакты CI хранятся 14 дней. Самостоятельная проверка исходников описана ниже.

## Один раз подготовить

1. Установите [uv по официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).
2. Получите исходники из [Crown](https://github.com/SverchkovVA/Crown):
   клонируйте репозиторий либо распакуйте свежий архив через **Code → Download ZIP**.
   При наличии клона обновляйте его командой `git pull --ff-only`.
   Если папка получена из старого ZIP, распакуйте новую версию в другую папку,
   чтобы не смешать исходники. Не переносите старую `.venv`.
3. Если uv установлен только что, откройте новое окно Проводника/PowerShell,
   чтобы новая запись PATH стала доступна.

Первое получение Python и зависимостей требует интернета. Проверяемые книги
создаются во временной папке и содержат только синтетические данные.

## Запустить проверку

В распакованной папке дважды щёлкните **check-windows.cmd**. Права администратора
не требуются. Окно остаётся открытым после завершения, чтобы был виден результат.

Лаунчер использует Windows PowerShell и ExecutionPolicy Bypass только для этого
процесса, не изменяя постоянную политику. Политики организации могут запретить
такой запуск; сценарий их не переопределяет.

Сценарий последовательно проверяет:

1. ОС, разрядность, доступность uv и зафиксированного Python.
2. Зависимости из uv.lock и передачу аргументов дочерним процессам.
3. Ruff, форматирование, Mypy и автоматические тесты.
4. Создание зашифрованной книги в пути с кириллицей и пробелами.
5. Повторное открытие по коду восстановления и отказ для неверного пароля.
6. Копию, восстановление с новой репликой, окно и закрытие книги.
7. Сборку EXE и повторение самопроверки уже собранным приложением.

При ошибке дальнейшие этапы останавливаются. Каждый запуск получает новую папку.

## Где результат

В `artifacts/windows-check-ДАТА-ИДЕНТИФИКАТОР/`:

- `report.json` — краткий отчёт для передачи в этот чат;
- `source-self-test.json` — самопроверка исходников;
- `tests.xml` — результаты pytest;
- `*.stdout.log`, `*.stderr.log` — подробные локальные журналы;
- `bundle/self-test.json` — самопроверка EXE;
- `bundle/app/PersonalFinance/PersonalFinance.exe` — программа после успешной сборки.

`report.json` не содержит парольных фраз, ключей, финансовых данных, имени
пользователя, имени компьютера или абсолютных путей. Подробные журналы могут
содержать пути к проекту; они остаются локальными. Ничего автоматически не отправляется.

После запуска приложите **report.json** к сообщению в этом чате. Даже при ошибке
он показывает последний выполненный этап. Если сценарий не удалось запустить,
скопируйте текст ошибки из окна.

## Что проверить руками после успешного прогона

Откройте собранный EXE, создайте тестовую книгу, добавьте счёт и категорию,
создайте копию, закройте книгу и восстановите копию в новую папку. Проверьте
читаемость при масштабе Windows 100/125/150% и работу с отключённой сетью.
Отдельно нужен запуск каталога программы на Windows без Python/uv.

Автоматический успех не завершает эти ручные пункты. В отчёте они всегда имеют
статус pending. `-Headless` предназначен для CI, допускает Windows Server и
использует offscreen; он не считается проверкой нативного окна Windows 11.

## Повторная приёмка исправлений 0.1.2

Не отправляйте парольные фразы, код PF1, key.json или базу в чат. Вводите
секреты только в локальном приложении. Для отчёта достаточно результата
действия без названий счетов, категорий и других личных данных.

1. Закройте приложение. Перед открытием существующей книги скопируйте **всю**
   её папку в отдельное новое место; исходную папку не заменяйте. Если приложение
   ещё держит книгу открытой, сначала завершите его обычным способом.
2. Запустите проверенный EXE 0.1.2 из полного каталога программы. Нажмите
   «Открыть книгу» и выберите папку существующей книги, содержащую `data`.
3. Введите парольную фразу либо полный код PF1. Для полного кода флажок
   «Использовать код восстановления» должен включиться автоматически.
   При вводе парольной фразы режим восстановления должен быть выключен.
4. Убедитесь, что сохранились ожидаемые счета, банки и категории. Выполните
   «Защита и копии» → «Проверить целостность книги».
5. Нажмите «Закрыть книгу» и **сразу**, без завершения программы и перезагрузки
   Windows, откройте ту же книгу повторно. Если доступны оба способа доступа,
   проверьте и пароль, и код PF1. Затем закройте окно программы, запустите её
   вновь и повторите открытие.
6. Создайте новую зашифрованную копию за пределами папки книги с отдельным
   паролем. Дождитесь сообщения, что копия создана и проверена, затем выполните
   «Проверить резервную копию» для этого же файла.
7. Восстановите эту копию в **новую** папку с новым паролем книги. Сохраните
   новый код восстановления отдельно. Сравните справочники, проверьте
   целостность, закройте и сразу откройте восстановленную книгу повторно.
8. Закройте восстановленную книгу и проверьте, что исходная по-прежнему
   открывается прежним способом доступа. Восстановление её не заменяет.

Если полный PF1 не включил флажок автоматически, отметьте это отдельно и
включите режим вручную. Укажите в результате, сработал ли ручной режим;
сам код не передавайте. В одном пользовательском сценарии это поведение
ещё требует объяснения, хотя синтетические регрессии проходят.

Если открытие не удалось, сохраните исходную папку и её отдельную копию.
Не удаляйте `.session.lock` принудительно и не меняйте ключевой файл.
Зафиксируйте версию программы, шаг и текст ошибки без секретов; не объявляйте
книгу повреждённой только по сообщению о неверном способе доступа.

Для отчёта отметьте отдельно: первое открытие существующей книги, повторное
открытие после кнопки, повторное открытие после закрытия окна, целостность,
создание/проверку копии и восстановление в новую папку. Автономный запуск,
масштаб Windows 100/125/150% и чистая Windows без Python/uv остаются отдельными
проверками; успешный автопрогон их не подтверждает.

## Проверка журнала 0.2.0.dev1

Сборка первой поставки этапа 4 и результаты: [отчёт этапа 4](stage-4-report.md).
Она размещается отдельно от стабильной 0.1.2. Создайте новую тестовую книгу.

1. Добавьте два счёта. Для первого задайте начальный остаток 1 000,00 RUB.
2. Добавьте доход 100,00, расход 25,00 и перевод 200,00 на второй счёт с комиссией
   1,00 RUB. Выберите расходную категорию комиссии. Используйте одну дату.
3. В «Счета» на эту дату должны быть 874,00 и 200,00 RUB.
4. Исправьте расход на 30,00: первый остаток станет 869,00. Удалите доход:
   первый остаток станет 769,00. История расхода должна содержать две версии,
   доход виден с флажком «Показывать удалённые» и перестаёт влиять на остатки.
5. Создайте/проверьте копию, восстановите её в новую папку. Сравните операции,
   историю, остатки и повторное открытие. Секреты вводите только в приложении.
6. Для книги 0.1.2 отдельно проверьте открытие справочников, копию и восстановление
   в новую папку: только восстановленная книга получает журнал. Сначала используйте
   синтетическую старую книгу. Исходная папка не заменяется.

Остаток на дату — конец выбранного дня. Будущие операции не входят в более раннюю
дату. Удаление сохраняет историю и не является необратимым стиранием записей.
Результаты сообщайте по шагам, без названий и секретов.

6. Удалите первый возврат: итог — 9 750,00, снова доступны 250,00 первой категории.
   Отдельно проверьте возврат на другой счёт той же валюты: приход отражается
   на выбранном получателе, лимит исходной покупки остаётся общим.

Это ручной сценарий, его успешное прохождение не предполагается автоматически.

## Сверка остатков — 0.2.0.dev5

[Текущая сборка и результаты](stage-4-reconciliation-report.md). Сверка работает
в книгах с журналом 0003–0006 без изменения схемы. Проверяйте синтетическую книгу.

1. Введите начальный остаток 10 000,00 RUB на 01.01.2026 и расход 1 000,00
   на 15.01.2026. В «Счета» выберите конец 31.01.2026: остаток 9 000,00.
2. Выделите счёт → «Сверить остаток». Введите 9 000,00 из тестовой выписки:
   результат должен сообщить о совпадении и показать две учтённые операции.
3. Повторите с 9 123,45: «В выписке больше на 123,45 RUB». Затем с 8 999,99:
   «В выписке меньше на 0,01 RUB». В таблице счетов должно остаться 9 000,00.
4. Измените дату сверки на 14.01.2026, сумму — 10 000,00: совпадение,
   в результат входит только начальный остаток.
5. Закройте январь в «Периоды» и повторите сверку: она доступна, месяц остаётся
   закрытым. После копии/восстановления в новую папку результат должен совпасть.

Сверка сравнивает введённую сумму, не импортирует строки выписки и не создаёт
корректирующую операцию. После правок журнала запустите её заново.

## Теги и сохранённые фильтры — 0.2.0.dev6

[Сборка тегов и доказательства](stage-4-organization-report.md). Для тегов
и сохранения условий нужна новая тестовая 0007 либо восстановленная копия старой
книги в новой папке. Обычный фильтр работает в 0003–0008 без обновления.

1. В «Теги и фильтры» создайте «Поездка». Добавьте два тестовых расхода 100,00
   и 200,00, назначив тег только первому через «Выбрать теги…» в форме операции.
2. В журнале нажмите «Фильтр…», выберите тег «Поездка». Должен остаться один
   расход 100,00, а остаток счёта по-прежнему учитывает оба расхода (−300,00 без
   начального остатка). «Сохранить как…» → «Поездки».
3. Сбросьте условия, выберите «Поездки» в списке и нажмите «Применить»:
   снова один расход. Измените условия и нажмите «Обновить»; в истории фильтра
   должны быть обе версии. Отдельно проверьте дату, счёт, категорию и текст.
4. Переименуйте тег, отправьте его в архив. Прежняя операция и сохранённый фильтр
   сохраняют связь; назначить архивный тег новой операции нельзя. Покажите архив
   и восстановите тег — новое назначение снова доступно.
5. Создайте/проверьте копию, восстановите в новую папку. Сравните теги, назначения,
   архив, историю и результат сохранённого фильтра; закройте/сразу откройте книгу.
6. Закройте месяц операции: изменение её тегов требует открытия с причиной.
   Изменение названия тега и условий списка не меняет денежные данные.

Группы фильтра применяются вместе; внутри группы достаточно одного значения,
а выбранные теги требуются все. Перевод считается одной операцией; фильтр банка
и счёта должен совпасть с одной его стороной. Ручной результат подтвердите отдельно.
