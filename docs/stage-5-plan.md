Установщик не запускался, системный PATH и упаковка Crown не изменялись.

У Tesseract есть модели русского языка, режим нескольких языков, TSV с координатами
и оценкой слова. CLI поддерживает stdin/stdout. Это позволяет исследовать передачу
PNG и TSV через каналы без временной открытой копии изображения; практическая
работа такого режима на Windows ещё должна быть проверена. Источники:
[модели](https://tesseract-ocr.github.io/tessdoc/Data-Files),
[TSV и языки](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html),
[CLI stdin/stdout](https://github.com/tesseract-ocr/tesseract/blob/main/doc/tesseract.1.asc).

Tesseract распространяется по Apache-2.0. Официальные tessdata_fast — целочисленные
LSTM-модели с компромиссом скорости/точности и Apache-2.0; это не доказательство
качества банковских сумм. Для сравнения нужны rus/eng и зафиксированные commit/SHA-256.
Источники: [руководство](https://tesseract-ocr.github.io/tessdoc/),
[tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast).

## Порядок прототипа

1. Подготовить воспроизводимый Windows x64 runtime в изолированном каталоге:
   точный выпуск/исходный commit, хеши EXE/DLL и моделей, лицензии зависимостей.
   Проверить автономный запуск и перенос каталога на чистую Windows. До этого
   не объявлять OCR готовым по установке на машине разработчика.
2. Отделить порт распознавания от банковских адаптеров: ограниченное изображение
   → слова/прямоугольники/оценки → черновики с происхождением полей. Запуск процесса
   без shell, с явным путём, тайм-аутом и без вывода распознанных данных в логи.
3. Создать только синтетический набор в Git: карточки светлой/тёмной темы,
   размеры/масштабы, символ рубля, пробелы/знаки, даты/время, неизвестный макет,
   обрезанные/двусмысленные поля. Подбор настроек и контрольный набор разделить.
4. Первым реализовать тип A Т-Банка. Сумма/валюта/направление/дата обязательны;
   неоднозначность требует исправления. Не подменять буквенные ошибки OCR цифрами
   молча. Деньги переводить в целые минимальные единицы через точный разбор.
5. Показать исходные области и оценки каждого поля, предложенную категорию,
   исправление и явное подтверждение. Правила dev9 могут предлагать категорию,
   ручное решение главнее. Само распознавание не сохраняет финансовых фактов.
6. Подключить подтверждение к общему финансовому пути с отдельным аудитом OCR.
   Существующий ImportKind ограничен CSV/OFX: нельзя маскировать изображение
   под банковский CSV или обходить проверку повторов. Новая схема/контракт аудита
   потребуют собственных проверок миграции и копии в новую папку.
7. Затем тип B, пересекающиеся изображения, частичные строки и адаптеры ВТБ/
   Яндекс Пэй. Тот же файл можно отличить по хешу; похожая дата/сумма в другом
   изображении сама по себе не доказывает дубликат. Свои переводы должны оставаться
   одной финансовой операцией с явно проверенной связью сторон.

## Измерение и данные

Измерять точное совпадение суммы/валюты/направления, даты/времени и полноту
обязательных полей; отдельно неизвестные форматы, лишние/потерянные операции,
повторы, скорость и ошибки движка. Процент распознанных букв не заменяет точность
финансового факта. Не обещать целевой процент до отдельного контрольного набора.

Пользовательские изображения, ожидаемые значения и распознанный текст не должны
попадать в Git, чат, CI, внешние OCR API или отчёты общего назначения. Частный
локальный прогон должен выводить только агрегированные метрики и версии/хеши
движка; содержимое изображений остаётся на ПК. Публичный Git/CI использует только
вымышленные данные. Для проверки макетов помогут локальные обезличенные примеры,
на которых настоящие имена/счета и финансовые значения заменены вымышленными.

Ручные пункты этапа 3 и приёмка финансового ядра остаются в прежних отчётах.
Источник инвестиционных котировок этим исследованием не выбирается.
