30.10.2026. Следующий срез после backend dev31; пока только прототип в
игнорируемом artifacts. В рабочий GUI ещё не перенесён: сначала требуются
успешные локальная сборка/source/EXE и оба CI согласованной схемы 0013.

## Поведение

В «Отчёты → Сохранённые сценарии вкладов» будет отдельный список названных условий:
поиск по названию, показ архива, расчёт выбранной версии, изменение условий,
создание независимой копии, переименование, архивирование/возврат и история.
Ни одно из этих действий не создаёт фактические выплаты или проводки.

Список — неизменяемый снимок. Команда действует только на явно выбранную строку,
без подстановки первой строки при пустом выборе или после фильтра.
Правка требует ожидаемую версию; конфликт не перезаписывает чужое изменение.
Копия имеет новый внешний UUID. Архив не удаляет старые версии; правка архивного
сценария сама по себе не возвращает его из архива. Историческую версию можно
рассчитать или скопировать, но нельзя переписать.

Все чтения/сохранения/расчёты выполняются рабочей задачей с общим mutex и проверкой
открытой сессии. Поздний результат не применяется к другой книге. До сохранения
пользователь видит прогноз и нажимает явную кнопку. Ошибка сохраняет введённое
название; отмена не создаёт версию. Старые книги 0002–0012 не мигрируются при открытии,
список для них недоступен; обычный прогноз без сохранения остаётся доступен.

## Точность загружаемых условий

Форма редактирует RUB; другие валюты доступны для просмотра/расчёта.
Суммы и ставки загружаются без float, идентификаторы начальной/последующих ставок
и движений сохраняются. Политики расчёта и точные даты выплат не угадываются.

Сохранённый DTO содержит даты выплат, а не исходное намерение «ежемесячно».
Поэтому после открытия форма показывает «Сохранённые даты выплат». Для иного срока
пользователь явно выбирает новый график; прежние даты не меняются незаметно.
Сама форма поддерживает до 1000 последующих ставок и 1000 движений; более крупный
сценарий остаётся доступен для просмотра/расчёта без частичной загрузки в редактор.

В прежней форме минимальная дата QDate(1,1,1) молча оставляла стандартный минимум
Qt 14.09.1752. Кандидат явно задаёт поддерживаемый Qt минимум 01.01.0100.
Сохранённые условия до 0100 года не подменяются; редактор отказывает до изменения
полей, просмотр/расчёт сохраняется. [Документация Qt](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QDateTimeEdit.html).
