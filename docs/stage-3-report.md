## Исправления 0.1.2 после ручной проверки

Дефект блокировки воспроизведён на отдельной синтетической книге: рабочий поток
создал сессию, основной поток закрыл её, но другой экземпляр FileLock не смог
получить системную блокировку. Причина — контекст FileLock по умолчанию
привязан к потоку. Вызов release из GUI не видел дескриптор рабочего потока.
В сессии теперь используется `thread_local=False`; операции сессии уже
сериализованы её RLock. Принудительное удаление блокировки не применяется.

Пользователь подтвердил ввод PF1 без флажка восстановления. В 0.1.1 такой ввод
проверялся как парольная фраза. Это объясняет сообщение об ошибке и само по себе
не доказывает повреждение ключевого файла. В 0.1.2 диалог распознаёт полный код
PF1 и включает соответствующий режим. При вводе кода внешние пробелы убираются;
парольные фразы не изменяются. Пользователь может явно изменить режим.

Добавлены проверки реального Qt-перехода из рабочего потока в GUI для создания,
открытия и восстановления: закрытие кнопкой/окном, немедленное повторное открытие
обоими способами, целостность, неизменность ключевого файла и переименование
закрытого каталога. Самопроверка исходников и EXE также проверяет передачу
сессии между потоками и повторное открытие после закрытия окна.

Локальный прогон 0.1.2: 59 тестов пройдены за 47,88 с; Ruff и форматирование
44 файлов, Mypy 30 файлов и усиленная самопроверка прошли.
