# Правила категоризации — 0.2.0.dev9

Требование 5.4.02, этапы 4–5. Историческое чистое ядро подготовлено в dev8;
в dev9 добавлены SQL/GUI и подсказки CSV/OFX. [Проверки](stage-4-classification-report.md).

## Условия и приоритет

Правило имеет UUID, название, вид «Доход»/«Расход», буквальный текст (1–200
печатных символов), категорию, целый приоритет 0–999, необязательный счёт и
признак включения. Сопоставление использует Unicode casefold, без regex и
изменения исходного описания. До 1000 включённых правил.

Больший приоритет применяется раньше. Разные категории на одном наивысшем
совпавшем приоритете возвращают конфликт для ручного выбора. Совпавшие правила
одной категории дают одну подсказку с отсортированными UUID правил; порядок
чтения из базы не определяет решение. Категория должна соответствовать виду
и существовать в этой книге; необязательный счёт также принадлежит книге.

Явная ручная категория/части всегда главнее. Перевод, начальный остаток и возврат
не классифицируются правилами: возврат использует категории исходной покупки.
Нет автоматического обучения, изменения прошлых операций, regex или OCR в этой
поставке. Структурированные контрагенты/уверенность OCR относятся к этапу 5.

## Данные и история

ClassificationInput отделён от OperationDraft: финансовая команда уже требует
категории. CategorySuggestion содержит статус, категорию, UUID правил и приоритет;
денег и команды записи в этом API нет. ClassificationSnapshot содержит неизменяемые
правила/категории, прочитанные одной SQL-транзакцией под RLock.

category_rule_revisions — типизированный payload сущности category_rule в 0009.
Общая версия is_deleted означает выключение. Изменения/выключение/включение
создают новую версию с ожидаемым родителем, хешем, журналом и квитанцией команды.
Включённые имена уникальны по casefold; выключенное имя можно использовать снова.
Повтор команды возвращает первоначальную версию, иной состав отклоняется.
SQL независимо защищает ссылки, родителя, уникальность/число и запечатанный payload.

Старые книги 0002–0008 открываются без обновления; правила недоступны. Переход
только через проверенную копию в новую папку с новыми паролем/PF1/репликой.
Схема 0009 сохраняет старые определения триггеров и финансовые версии/хеши.
Формат ключей и контейнер копии v1 не меняются. [ADR-0010](adr/0010-category-rules.md).

## Интерфейс и импорт

«Правила категорий»: создать, изменить, выключить/включить, показать выключенные,
история. Определения хранятся в SQLCipher и зашифрованной копии; не добавляются
в открытый экспорт журнала. Названия/тексты отображаются буквально.

В настройках импорта есть «Предлагать категории по правилам», включённый по
умолчанию при доступной 0009. Общая выбранная пользователем категория имеет
приоритет. Для NEW/POSSIBLE без неё правила предлагают категорию; исходные
DUPLICATE/CONFLICT импорта не изменяются. Сопоставление выполняется в рабочем
потоке до показа таблицы, не создаёт финансовых фактов.

В таблице видны категория и объяснение правила (до трёх названий и число остальных).
Конфликт требует ручного выбора. Ручная правка/части или связь с существующей
операцией не запускают правило заново. Изменение правила после подготовки не
меняет просмотренный снимок. Сохранение выполняет прежний Importing.confirm
только после явного подтверждения; все денежные инварианты проверяются снова.
