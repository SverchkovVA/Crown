# Подготовка правил категоризации — требование 5.4.02

Чистое ядро `domain/classification.py` подготовлено после экспорта 0.2.0.dev8.
Пользовательского управления правилами, SQL-хранения и подключения к импорту
пока нет. Этот документ фиксирует проверенную логику и границы следующей поставки,
а не объявляет автоматическую категоризацию доступной в интерфейсе.

## Проверенная логика

- Правило имеет UUID, название, вид «Доход»/«Расход», буквальную подстроку,
  категорию, приоритет 0–999 и необязательное ограничение одним счётом.
- Сопоставление текста использует Unicode casefold, без регулярных выражений,
  сетевых сервисов, изменения исходного текста или финансовых сумм.
- Работает больший приоритет. Если на нём разные категории, результат — конфликт
  для ручного выбора. Совпавшие правила одной категории дают одну подсказку.
  UUID правил отсортированы, порядок загрузки не определяет решение.
- Явная ручная категория либо части всегда сохраняются. Подсказка не заменяет
  их даже при устаревшем правиле. Для перевода, остатка и возврата правил нет:
  возврат использует категории исходной покупки.
- Выключенные правила пропускаются. Категория совпавшего правила должна
  существовать и соответствовать направлению. Некорректные/повторные UUID,
  типы, пустые тексты и более 1000 правил отклоняются.

ClassificationInput отделён от OperationDraft: полноценная финансовая команда
уже требует категории. CategorySuggestion возвращает статус, категорию, UUID
правил и приоритет; денег и команды записи в этом API нет.

## Фактическая проверка

37 синтетических unit-тестов прошли за 0,35 с; Ruff/форматирование и Mypy
(70 файлов) прошли. Покрыты Unicode, буквальные спецсимволы, счёт/направление,
перестановки правил, конфликт/совпадение приоритетов, ручная категория/части,
неподдерживаемые виды, некорректные ссылки и входные данные.
Полный Windows/CI-набор с этим ядром ещё не запускался. [Экспорт](stage-4-export-report.md)
проверялся отдельно до добавления этих двух файлов.

## Следующее подключение

Правила должны храниться в зашифрованной книге с версиями, квитанциями команд,
историей и проверкой ссылок. Их правка не меняет прежние операции. При импорте
подсказки видны до подтверждения; ручное исправление остаётся главным.
До реализации/проверок SQL, GUI, копии и миграции это только подготовка.
