## Контракт ядра

`prepare_journal_export(operations, settings, institutions=None)` принимает tuple
текущих операций, по одной версии каждого UUID, и ExportSettings. Применяет
OperationQuery по периоду, счетам, банкам, категориям, видам, тексту и тегам.
Связи счетов и банков обязательны при банковском фильтре. Переданный снимок
не меняется. Результат ExportPreview неизменяем и сортируется по дате/UUID.
Перевод остаётся целой операцией с обеими сторонами и комиссией. Удалённые
версии включаются только через явный include_deleted.

`serialize_journal_export(preview, format)` возвращает bytes, ничего не пишет
и не отправляет. JSON UTF-8 версии 1 содержит `format=crown-journal-export`,
`money_encoding=integer_minor_decimal_string` и массив operations. Денежные
amount_minor/fee_minor/части — десятичные строки целых минимальных единиц;
валюта и exponent указываются отдельно. Это сохраняет int64 даже в потребителях
JSON с ограниченной точностью чисел. Само приложение продолжает считать целыми.

CSV UTF-8 BOM, `;`, CRLF имеет фиксированные машинные заголовки и одну строку
на операцию. Части/теги представлены JSON-ячейками; целые денежные значения
передаются десятичным текстом. При открытии в Excel большие значения следует
импортировать как текст: CSV не задаёт тип ячейки. Примечания с начальным
оператором формулы, включая пробелы/перенос/BOM до него, получают апостроф.
JSON сохраняет исходное примечание при его явном включении.

Примечания и UUID тегов выключены по умолчанию. Условие текстового поиска не
попадает в результат даже при исключённых примечаниях. Имена книг, пароли/PF1,
ключи, raw-импорт, пути, реплики и квитанции не являются полями формата.
Имена справочников пока не входят: присутствуют стабильные UUID ссылок.
Сериализация не меняет состояние снимка, суммы, баланс или историю.
