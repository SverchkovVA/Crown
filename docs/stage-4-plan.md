# Этап 4: журнал и балансы

Пользователь разрешил следующий этап 26.10.2026. Ветка разработки: stage-4-ledger.
Стабильная main 0.1.2 сохраняется для ручной приёмки этапа 3.

## Первая поставка

- Календарная финансовая дата; начальный остаток, доход, расход, перевод.
- Комиссия перевода — отдельная расходная проводка той же операции.
- Целые минимальные единицы, проверка int64, без float.
- Внутренние счета активов, доходов, расходов и начальных остатков.
- Операция, проводки, версия, журнал и квитанция команды атомарны.
- Исправление через новую версию с ожидаемым предшественником; удаление — tombstone.
- Только принятые версии участвуют в остатках; переводы не создают доход/расход.
- Балансы на дату и журнал в русском интерфейсе.
- Неполная ручная приёмка этапа 3 остаётся в отчёте.

## Совместимость и проверка

Схема 0003 нужна для финансового журнала. Старые книги 0002 открываются без
финансовых функций. Обновление выполняется через проверенную зашифрованную
копию и восстановление в новую папку: миграция только промежуточной базы,
новые пароль/код и реплика. Исходная книга и копия не заменяются.

Проверки: точные проводки, отрицательный/нулевой начальный остаток, комиссия,
отказ неверных ссылок/валют, повтор команды, устаревшее исправление, история,
отмена операции, переполнение, откат частичной записи, копия/восстановление,
миграция схемы 0002 только на копии, GUI и аварийная остановка процесса.

Разделение доходов/расходов добавлено в следующую поставку 0.2.0.dev2:
см. docs/stage-4-split-report.md. В 0.2.0.dev3 добавлены связанные возвраты,
см. docs/stage-4-refund-report.md. В 0.2.0.dev4 добавлено локальное закрытие месяцев,

В 0.2.0.dev7 добавлен локальный ограниченный CSV/OFX-импорт с предпросмотром
и единым подтверждением; см. docs/stage-4-import-report.md. Требуются ручная
