# Локальный CSV/OFX-импорт — 0.2.0.dev7

Разрешённое расширение A2 этапа 4, ветка stage-4-ledger. Main сохраняет 0.1.2.
[Предыдущая поставка тегов](stage-4-organization-report.md). Только синтетические
данные; полный этап 4 и ручная приёмка ещё не завершены.

## Реализовано

Локальный файл → настройки → предпросмотр/исправление/выбор → явное подтверждение.
CSV требует заголовок и сумму со знаком, поддерживает UTF-8/Windows-1251,
`;`/`,`/табуляцию, ДД.ММ.ГГГГ/ГГГГ-ММ-ДД, десятичную точку/запятую.
Описание, внешний ID и код RUB необязательны. OFX поддерживает ограниченные
1.x SGML/2.x XML, проведённые STMTTRN одного RUB-счёта. Дата берётся в календаре
выписки, без пересчёта ОС. Ожидающие движения не записываются; корректировки
банка и дополнительные валюты показываются исключёнными ошибками.

Настройка общих категорий не пишет данных. Строка уточняется общей формой:
сумма, дата, категории/части, перевод, связанный возврат, теги. Исходный снимок
остаётся отдельным от исправленного. RUB и направление счёта сохраняются,
начальные остатки исключены. Ограничения — 8 МиБ/2000 строк, без сетевых загрузок,
DTD/ENTITY и внешних изображений. Ошибочную строку можно исключить либо исправить
в исходном файле и загрузить заново. [ADR-0008](adr/0008-statement-import.md).

Ключи внешних ID/области счёта защищают от повторных выгрузок; без ID точная
защита действует для того же файла/номера строки. Совпадение даты/суммы требует
решения: возможный повтор автоматически не отмечен. Явная связь с текущей
версией существующей операции не создаёт повторного движения; обе стороны
банковской выписки можно связать с одним переводом по своим счетам.

Подтверждение использует одну SQL-транзакцию/RLock и общий путь финансовых
версий. Ошибка любой строки откатывает операции/проводки/историю/квитанции/
аудит/ключи повторов/последовательность. Конечные дневные остатки проверяются
после всей группы, без ложного промежуточного переполнения. Копия и новая
реплика сохраняют защиту от повтора; повтор команды возвращает исходный снимок.

## Совместимость

Схема 0008 добавляет аудит подтверждённых групп и строк, читает 0002–0008.
Прежние книги при открытии не меняются; импорт доступен только в 0008.
Переход 0002/0003/0004/0005/0006/0007 → 0008 только через проверенную копию и новую
папку восстановления. Новые пароль/PF1/реплика; UUID истории сохраняются.
Миграции 0001–0007, финансовые хеши/квитанции и криптографические форматы прежние.
Зависимости не заменялись; в uv.lock меняется только версия локального пакета.
Аудит пока локален, сетевого протокола нет.
