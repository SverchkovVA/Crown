# Архивные пакеты OCR: частичные доказательства 06.11.2026

Отдельная ветка ocr-provenance-preparation. Рабочий OCR-модуль, модели,
приложение и криптографические форматы не менялись. Ни один скачанный DLL
не выполнялся и не копировался в готовое приложение.

## Установлено фактически

Проверены десять небольших пакетов из
[официального архивного репозитория MSYS2](https://repo.msys2.org/mingw/mingw64/).
Имена получены из индекса; архивы не устанавливались. Штатный Windows tar
прочитал только метаданные, нужные DLL и уведомления в новый технический каталог.
Полное распаковывание и исполнение PKGBUILD не выполнялись.

Точное совпадение с SHA-256 закреплённого runtime найдено у шести из 56
нативных файлов (EXE + 55 DLL):

| Пакет | Совпавшие файлы |
|---|---|
| libb2 0.98.1-3 | libb2-1.dll |
| bzip2 1.0.8-3 | libbz2-1.dll |
| jbigkit 2.1-5 | libjbig-0.dll |
| brotli 1.2.0-1 | libbrotlicommon.dll, libbrotlidec.dll |
| giflib 6.1.3-1 | libgif-7.dll |

Для libb2 и giflib дополнительно совпал SHA-256 архива со страницей пакета:
[libb2](https://packages.msys2.org/packages/mingw-w64-x86_64-libb2),
[giflib](https://packages.msys2.org/packages/mingw-w64-x86_64-giflib).
Другие проверенные версии Brotli/GIF не совпали и сохранены как несовпадения.
Версия не выбиралась только по имени DLL.

Пять совпавших бинарных архивов имеют подписи GOODSIG/VALIDSIG, exit0 GnuPG2.4.9.
Проверка выполнена с изолированным homedir, без личных ключей,
автоматического получения ключей и запуска агента. Официальный
[набор открытых ключей MSYS2](https://github.com/msys2/MSYS2-keyring/blob/main/msys2.gpg)
сверен с Git blob7be83b5cc7bc69003ad9cc76ce65b4314c0b71a1.
Подписанты и их первичные ключи не найдены в прочитанном
[списке отозванных](https://github.com/msys2/MSYS2-keyring/blob/main/msys2-revoked),
blob38db966082240362b21a1cd1e66d6dc50d67f34d.

GPG сообщает TRUST_UNDEFINED: цепочка сертификации/доверия целиком не принята.
Подлинность подписи относительно скачанного набора не означает завершённого
лицензионного аудита или общего разрешения распространения.

## JBIG-KIT: отдельный источник

[Архив исходного пакета 2.1-5](https://repo.msys2.org/mingw/sources/mingw-w64-jbigkit-2.1-5.src.tar.zst)
также имеет проверенную подпись. SHA-256 PKGBUILD совпал с pkgbuild_sha256sum
из .BUILDINFO совпавшего бинарного пакета. В архиве есть рецепт, патчи и
jbigkit-2.1.tar.gz; SHA-256 вложенного upstream-архива присутствует в рецепте.
Рецепт не выполнялся, повторная сборка и полная проверка всех патчей не сделаны.

Это уточняет прежнее неизвестное происхождение libjbig-0.dll.
Семейство [jbigkit в MSYS2](https://packages.msys2.org/packages/mingw-w64-x86_64-jbigkit)
указывает GPL-2.0; метаданные конкретного совпавшего пакета сохранены.
Условия всего комплекта и требуемые материалы ещё должны быть проверены.
Простая замена на новую DLL не выполнялась.

## Проверки и границы

Offline-инструмент и связанная проверка происхождения сборки: 25 passed, 0.57 с.
Ruff/формат двух файлов passed. Реальный запуск инструмента: 6/56 совпадений,
десять каталогов пакетов, без доступа к финансовым данным.
[Машиночитаемое доказательство](ocr-package-evidence-20261106.json).

В byte_evidence поля package_signature_verified=false означают, что сам
offline-инструмент подписи не проверяет. Отдельный результат GPG расположен
в signature_evidence. Поле application_bundled=false относится к этому
инструменту: он ничего не подключает к приложению и не инвентаризирует
отдельные локальные каталоги поставки. В соседних проверочных сборках Crown
есть ранее подготовленный ocr-runtime; этот отчёт его не меняет.

Полный лицензионный аудит, остальные 50 нативных файлов, отдельная цепочка
Ubuntu MinGW для двух GCC DLL, исходники/патчи и цепочка доверия остаются.
Наличие LGPL/GPL/других уведомлений нельзя устанавливать по одному имени DLL.
Никакие флаги готовности или разрешения поставки не включены.

Старый рецепт Tesseract ссылается на MSYS2-keyring/master; при текущей проверке
эта ветка дала404, репозиторий использует main. Для отдельной проверки взят
фактический официальный blob с проверкой его хеша. Upstream-рецепт не менялся,
полная воспроизводимость исторической среды этим не доказывается.

Локальные архивы/ключи/компонентный JUnit находятся в игнорируемых artifacts.
В Git входят только исходники инструмента, технические хеши, публичные ссылки
и отчёт. Снимки банков, книги и секреты не использовались.
