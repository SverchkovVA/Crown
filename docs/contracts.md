# Контракты

## Реализованные сценарии

- `create_vault(destination, name, password)` создаёт новую книгу и возвращает
  открытую сессию с отдельным кодом восстановления. Назначение не перезаписывается.
- `open_vault(root, credential, recovery=False)` проверяет формат, ключ, версию
  схемы, целостность и блокировку. Отсутствующий файл базы не создаётся.
- `Catalog.add_institution/add_account/add_category` валидируют ввод и передают
  команду адаптеру. Типизированные результаты не содержат ключей.
- `create_revision` сохраняет сущность, версию, группу, голову, журнал и квитанцию
  одной транзакцией. Тот же ID и тот же запрос возвращают прежний результат.
  Повтор ID с другим запросом вызывает ошибку.
- `VaultSession.check_integrity()` проверяет страницы, внешние ключи, принятые
  версии и наличие изменений в журнале.
- `Ledger.add(draft, command_id=None)` сохраняет полный сбалансированный набор
  проводок и возвращает Operation. Идентификатор команды необязателен для
  локального вызова; адаптер создаёт UUID, если он не передан.
- `Ledger.replace(id, expected_revision_id, draft, command_id=None)` создаёт
  новую версию только при совпадении принятого предшественника.
- `Ledger.delete(id, expected_revision_id, command_id=None)` сохраняет версию
  удаления. Предыдущие версии неизменяемы; удалённая операция не влияет на баланс.
- `Ledger.operations(include_deleted=False)`, `history(id)` и `balances(as_of=None)`
  читают принятые версии, полную линейную историю и остатки на конец даты.
  Без as_of баланс включает все даты; UI всегда передаёт выбранную дату.
- Один активный начальный остаток на счёт; он допускает ноль/отрицательное число.
  Движения не могут предшествовать его дате. Доход/расход/перевод/возврат положительны;
  комиссия перевода неотрицательна и требует расходную категорию при ненулевой сумме.
  Перевод требует разные счета одной валюты.
- Переполнение int64 любого остатка в конце любой финансовой даты отклоняет всю
  команду. Промежуточное сложение выполняется Python int, без SQLite SUM/float.
- Целостность включает хеши всех финансовых версий, точное совпадение проводок,
  ссылки и цепочки предшественников; порядок не зависит от часов устройства.
- `OperationDraft.parts` — tuple из 2–100 OperationPart для дохода/расхода/возврата:
  category_id отсутствует, категории уникальны, суммы положительны одной валюты
  и точно равны общей. Порядок частей сохраняется в версии/хеше. Пустой tuple
  сохраняет прежний контракт обычной операции. Переводы/остатки не разделяются.
- `Ledger.supports_splits` сообщает доступность разделения (схема 0004 и новее).
  Схема 0003 поддерживает обычный журнал; попытка записать части отклоняется
  без изменений и предлагает восстановить копию в новую папку.
- `Ledger.supports_refunds` сообщает доступность возвратов (0005).
- `Ledger.refund_candidates(excluding_refund_id=None)` возвращает активные
  покупки и доступные остатки по категориям, включая полностью возвращённые.
  При исправлении исключается собственная сумма действующего возврата.
- REFUND требует `refund_of` и `refund_of_revision_id` одной книги. Новый запрос
  требует текущую принятую версию неудалённого EXPENSE; устаревший просмотр
  отклоняется. Исторический снимок остаётся проверяемым после правок покупки.
  Дата не раньше покупки, валюта та же; счёт получения может отличаться.
- Проводки возврата уменьшают расходы на его дату. Совокупная сумма по каждой
  категории не превосходит текущий расход. Несовместимая правка/удаление покупки
  и превышение при конкурирующих командах отклоняются атомарно. Удаление возврата
  освобождает доступную сумму. Тот же идентификатор команды возвращает старый результат.
- `VaultSession.periods` доступен в 0006 и новее, в старых схемах равен None.
- `Periods.states()` возвращает состояния месяцев с историей; отсутствие месяца
  означает открытый период. `history(month)` возвращает цепочку от закрытия.
- `Periods.close(month, expected_revision_id=None, reason="", command_id=None)`
  закрывает месяц. Повторное закрытие ранее открытого требует ожидаемую версию.
- `Periods.reopen(month, expected_revision_id, reason=..., command_id=None)`
  явно открывает закрытый месяц, требует непустую причину. Состояния неизменяемы,
  повтор команды безопасен, устаревшая версия отклоняется.
- Все виды операций защищены по новому и прежнему месяцу, включая удаление,
  части, переводы, возвраты и изменение примечания. Просмотр/копии доступны;
  справочники не имеют финансовой даты и этим запретом не блокируются.
- Контроль удалённых изменений при будущей синхронизации ещё не реализован.
- `Ledger.reconcile(account_id, as_of, statement_balance)` читает остаток и
  принятые операции счёта в одной транзакции под общим RLock. Возвращает
  Reconciliation: остаток книги/выписки, точную разницу и учтённые операции.
  Включает обе стороны перевода, комиссию источника, части и возвраты;
  удалённые/будущие версии исключены. Чужой счёт/валюта и неверный ввод отклоняются.
- Сверка ничего не записывает, не создаёт корректировки и не открывает закрытый
  месяц. Разница — Python int: она может превышать диапазон одной Money при
  сравнении двух допустимых крайних остатков. Доступна в 0003–0011 без миграции.
- `Ledger.supports_tags` — доступность назначений (0007); `OperationDraft.tag_ids`
  содержит 0–100 уникальных UUID, канонически отсортированных. Пустой набор
  не добавляет ключ в прежний payload. Назначение/снятие — новая версия операции.
- `Ledger.search(OperationQuery)` читает только текущие версии, применяет условия
  к журналу и не меняет расчёт балансов. Работает в 0003–0011; теги требуют 0007.
- `VaultSession.organization` доступен в 0007/0008/0009/0010/0011. `tags/filters` читают активные
  либо архивные записи; add_tag/rename_tag/archive_tag и save_filter/rename_filter/
  archive_filter создают версии с ожидаемым предшественником и идентификатором команды.
  history возвращает полную линейную цепочку. Повтор команды использует исходный
  снимок, а не более позднее название/состояние. Архив обратим и сохраняет назначения.
- Условия фильтра имеют версию 1 и строгий набор полей. Неизвестные поля/версии,
  неверные даты/UUID/виды и чужие ссылки не сохраняются. Сохранённые условия
  могут ссылаться на архивные записи для поиска истории. Сетевой обмен — будущий этап.
- `VaultSession.importing` доступен в 0008/0009/0010/0011, в старых схемах равен None.
- `Importing.columns/parse_csv/parse_ofx` читают байты, не меняют книгу.
  ImportDocument содержит валидные исходные строки, видимые ошибки и предупреждения.
  Ошибочные строки нельзя подтвердить; файл можно исправить и прочитать снова.
- `preview(document, account_id)` читает один снимок под RLock и возвращает
  NEW/POSSIBLE/DUPLICATE/CONFLICT. Известный ключ с другим исходным содержимым
  блокируется. Возможное совпадение даты/суммы требует решения пользователя.
- `confirm(document, account_id, selections, command_id=None)` повторно проверяет
  источник/счёт, закрытые месяцы, ссылки, проводки и конечные дневные остатки.
  1–2000 выбранных строк записываются одной транзакцией с аудитом и квитанцией.
  Каждая ImportSelection содержит исправленный OperationDraft либо явную связь
  с текущей ожидаемой версией. Начальный остаток исключён; валюта RUB и направление
  движения выбранного счёта сохраняются. Сумму/дату/категории можно исправить.
- Связь не создаёт финансовой версии: дата/движение счёта должны точно совпасть
  с исходной строкой. Две стороны банковского перевода связываются с одной
  операцией независимо по своим счетам. Внутри группы две строки одного счёта
  не связываются с одной операцией. Устаревшая версия отклоняется.
- Та же команда с тем же составом возвращает первоначальный ImportResult;
  иной состав вызывает ошибку. Новая команда для уже известного ключа не
  дублирует операции, в том числе после удаления/копии/новой реплики.
- `create_backup`, `verify_backup`, `restore_backup` описаны отдельно.

SQL-запросы параметризованы. Названия таблиц выбираются только из внутренних
констант. Пароли не принимаются через аргументы CLI и не попадают в SQL URL.

## Сохранённые будущие контракты

- OCR использует общие финансовые инварианты и отдельное явное подтверждение.
  Порт, опытные A/B Т-Банка/ВТБ, проверка полей и финансовый контракт dev10 описаны ниже.
- Расчёт процентов принимает версии условий и фактические движения, возвращает
  график и предположения; не создаёт банковскую выплату.
- Прогноз принимает факты, планы и предположения, не создаёт фактические операции.
- QuoteProvider принимает только публичные идентификаторы инструментов.
  Количество бумаг, суммы и счета ему не передаются.
- RefreshPrices вызывается только кнопкой. PortfolioValuation читает локальные
  цены и никогда не инициирует сеть.
- Sync передаёт версии и атомарные группы с повторной доставкой и подтверждением
  после записи. Финансовые конфликты не разрешаются временем устройства.

Для Android общими будут схемы, денежные правила и контрольные примеры, а не
Python-объекты и не требование одинаковой физической схемы SQLite.


## Экспорт журнала

- `VaultSession.exporting` доступен при наличии журнала (0003–0011), иначе None.
- `Exporting.preview(ExportSettings)` возвращает согласованный ExportPreview
  текущих версий. OperationQuery выбирает период/счета/банки/категории/виды/текст/теги,
  сохраняя целую операцию. Удалённые факты включаются только явно.
- Названия включены по умолчанию; примечания и теги — нет. Условия текстового
  поиска и внутренний UUID книги не являются полями результата. Названия тегов
  и частей также исключаются при include_names=False.
- `Exporting.save(destination, preview, format)` сохраняет просмотренный снимок
  при открытой сессии той же книги, вне её папки, под новым именем. Поздние изменения
  фактов/названий не меняют подготовленный результат. Книга/квитанции не записываются.
- Файл создаётся через собственное исключительное временное имя, flush/fsync
  и публикацию без замены существующего имени. Коллизия/ошибка не удаляет чужой
  файл. Формат и расширение должны совпадать; CSV/JSON — открытые данные.
- Состав/формат версии 1 описаны в [контракте файла](export-format-draft.md).
  Журнальный CSV отвергается банковским импортом по сигнатуре заголовков.
  Восстановление полной книги из этого экспорта не поддерживается.

## Правила категорий

- `VaultSession.classification` доступен в 0009–0011, иначе None.
- `rules(include_disabled=False)`, `history(id)`, `save(CategoryRule,
  expected_revision_id=None, command_id=None)` сохраняют линейные версии.
  UUID нового правила задаётся до команды; повтор возвращает первоначальную
  версию, иной состав того же command_id отклоняется.
- `snapshot()` читает неизменяемые правила/категории согласованно. `suggest(input)`
  не пишет книгу. Больший приоритет раньше; разные категории на одном приоритете
  возвращают конфликт. Ручная категория/части главнее. Перевод/остаток/возврат
  не получают категорий правил. [Подробности](classification-rules-draft.md).
- `prepare_import_categories` обрабатывает NEW/POSSIBLE в рабочем потоке;
  DUPLICATE/CONFLICT исходного импорта не получают новых подсказок. Общая ручная
  категория имеет приоритет. GUI сохраняет исправленную строку и не запускает
  правило заново после ручной правки/связи. Финансовые записи создаёт прежний
  `Importing.confirm` только после явного подтверждения.


## Локальный OCR — первый технический срез этапа 5

- Ocr.recognize(OcrImage) обращается к OcrEngine, возвращает неизменяемый
  OcrDocument с тем же отпечатком входного PNG и размерами. Сценарий работает
  без открытой книги; финансовые команды и сохранение отсутствуют.
- Загрузчик load_ocr_image/decode_ocr_image принимает PNG/JPEG до 12 МиБ,
  стороны до 10 000 и до 20 млн пикселей; применяет EXIF-поворот, нормализует
  в PNG в памяти, удаляет метаданные и заменяет прозрачность белым фоном.
  Возвращает отдельные SHA-256 исходника и нормализованного входа.
- OcrDocument хранит исходный текст каждого слова, область, Decimal-оценку
  0–100, ключ строки/номер слова, версию движка и SHA-256 моделей. Оценка слова
  не доказывает правильность суммы/даты. Буквы не заменяются цифрами.
- TesseractRuntime требует явный абсолютный каталог и перечень хешей файлов.
  Перед вызовом проверяются EXE/DLL/модели. TesseractEngine передаёт PNG через
  stdin, разбирает UTF-8 TSV из stdout; без shell и сетевых загрузок.
  Пределы: 30 с по умолчанию (1–120), stdout 4 МиБ, stderr 64 КиБ,
  25 000 строк TSV и 10 000 слов; одна страница с согласованной геометрией.
- Подтверждение финансов, аудит OCR и защита повторов изображения реализованы
  отдельным срезом dev10, см. ниже. Опытные окна проверки полей описаны ниже. ImportKind.CSV/OFX остаётся прежним.
  [Границы доказательств](stage-5-ocr-report.md), [ADR-0011](adr/0011-local-ocr-port.md).


## Карточка и история OCR — опытный срез 28.10.2026

CardRecognition получает порты загрузки, Ocr, адаптеров и явный bank_name
(Т-Банк/ВТБ; в dev13 также «Любой банк» только для предпросмотра);
MainWindow внедряет коллекцию профилей. preview(path) возвращает
OcrCardPreview, history(path) — OcrHistoryPreview; результат связан с исходным
SHA-256 и нормализованным входом. LoadedOcrImage теперь доменный DTO без Qt.

OcrCardDraft хранит поля с индексами слов/причинами проверки; OcrHistoryDraft —
до 100 предложений и число денежных фрагментов вне строк. Внутренний review_card
принимает набор четырёх подтверждённых полей и признак одной проведённой операции,
проверяет значения и возвращает ReviewedOcrCard с изменёнными полями. Отдельного
флажка одной операции в UI dev11 нет; явная кнопка проверяет заполненные значения,
а видимые флажки зависят от настройки. Это результат в памяти, не финансовая команда.
Исходные неизвестные поля не меняются; год/валюта могут предлагаться по настройке,
относительные или противоречивые даты не угадываются. Финансовый путь проверяет
вид/счета/категории; итоговое окно также отключается. [Текущий контракт](ocr-workflow-contract.md).

## Финансовое подтверждение OCR — 0.2.0.dev10

- `VaultSession.ocr_importing` доступен в 0010/0011, иначе None.
- `OcrImporting.prepare(preview, reviewed, account_id, draft)` возвращает
  неизменяемый OcrSelection с воспроизводимым OcrEvidence. Проверяет тот же
  источник, полную дату, RUB и точное движение счёта; OPENING запрещён.
- `preview(selection)` возвращает NEW/POSSIBLE/DUPLICATE/CONFLICT. Точный источник,
  пересечение суммы и иной контекст того же изображения блокируют новую запись.
  Совпадение даты/движения с иной операцией требует ручного решения.
- `confirm(selection, command_id=None)` заново проверяет состояние и атомарно
  сохраняет финансовую версию либо связь, квитанцию и происхождение. Связь требует
  актуального revision_id и не создаёт проводок. Прежний UUID возвращает прежний
  результат; другой состав UUID и новый UUID для принятого источника отклоняются.
- `check_integrity()` проверяет пакет/хеши/ссылки/историческую версию и контекст;
  вызван из общей проверки VaultSession. Аудит переносится через копию с запретом
  повторов после смены реплики. Одно подтверждение строки за проход.

Полный формат и границы: [контракт](ocr-confirmation-contract.md),
[результаты](stage-5-confirmation-report.md).

## Список и предпочтения OCR — dev11

- OcrReviewDefaults(currency,reference_year,confirm_fields), suggest_corrections
  возвращают предложения. Raw-поля не изменяются. Отдельной галочки одной операции
  в UI нет; четыре флажка и итоговое окно зависят от настроек.
- CardRecognition(...,fallback_ocr=None) может один раз повторить неполную
  незаблокированную карточку. Выбирается целый более полный документ без
  противоречий/потери известных полей. История не переключает режим автоматически.
- VaultSession.ocr_importing доступен в 0010/0011, supports_batches — только 0011.
  preview_many(tuple), confirm_many(tuple,command_id=None) принимают 1–100 строк;
  сохранение атомарно, повтор родительского UUID возвращает исходные результаты.
- VaultSession.ocr_settings доступен только в 0011. load() возвращает снимок/UUID
  либо None/None; save(preferences,expected_revision_id) добавляет неизменяемую
  версию и меняет указатель. check_integrity проверяет цепочку/хеши/счета.
- PNG получает фиксированные 3937 точек/м по осям. Равный исходный file_sha256
  с другим image_sha256 не создаёт новую финансовую запись.

[Точный контракт и ограничения](ocr-workflow-contract.md).

## Уточнение дат и категории списка — dev12

card_date_match(text) разбирает дату целиком, допуская известный одиночный значок
навигации перед ней; это не поиск даты в произвольном тексте. Для дня/месяца без
года OcrReviewDefaults предлагает заданный год, raw-поле не становится известным.

OcrBatchDialog(...,classification:ClassificationSnapshot|None=None) получает снимок
правил/категорий при открытии. Флажок подсказок действует только в этом списке.
Подсказка учитывает вид, счёт и описание; повторный расчёт не меняет ручной выбор.
При включённых подсказках равный приоритет разных категорий оставляет категорию незаданной, запись всего
выбранного набора заблокирована до ручного выбора. Свои переводы/исключения обходят
этот путь. Подсказка не записывает фактов и не пересчитывает прошлые операции.
Одиночная финансовая форма OCR остаётся с ручной категорией. Схема 0011 неизменна.

## Общий профиль dev13: проверка без записи

UNIVERSAL_PROFILE = «Любой банк», идентификаторы generic-card-v1/generic-history-v1.
Это профиль разбора, не определение банка или подлинности документа. analyze(path)
возвращает OcrCardPreview либо OcrHistoryPreview, сохраняя связь с исходным входом.
Список выбирается при нескольких кандидатах с контекстом дат/истории либо одной
строке под заголовком истории. Нет последовательного открытия формы каждой строки.
Общий список принимает importing=None; prepare() заполняет reviewed_cards,
saved_count остаётся 0, Job и команды журнала не создаются. Карточка не имеет
кнопки подготовки финансов. В dev13–16 make_ocr_evidence отвергал новый профиль.
В dev17 декодер принимает согласованные пары «Любой банк»/generic-*; запись
разрешена репозиторием только в 0012. В 0010/0011 общий профиль отвергается до записи.
GUI общего профиля пока сохраняет режим без записи до полного подтверждения backend. Настройки счетов/исключений/категорий
не применяются к этому предпросмотру.
Дата/сумма могут находиться в разных колонках; дневной итог/номер/остаток не
становится операцией по одному наличию числа. Неоднозначность, известная другая
валюта, непроведённый статус и комиссия видны как причины отказа. Нельзя объявлять
полноту списка по числу кандидатов. [Текущий срез](stage-5-universal-report.md).

## Доходы/расходы только для чтения — dev14

ReportPeriod принимает две календарные даты включительно, начало ≤ конец.
Analytics.report берёт текущие неделённые по версиям операции под mutex;
income_expense_report отвергает повтор ID (история не подменяет текущий журнал),
пропускает удалённые/внешние даты и использует существующие проводки. Итоги,
категории и месяцы содержат точные Python int, включая суммы свыше int64 одного
хранимого движения. Разница = доход − расход; отрицательный расход допустим при
возврате покупки прошлого периода. Общая валюта не вычисляется, курсов нет;
разные определения одного кода валюты отвергаются. Отчёт содержит ссылки ID/версии
учтённых операций. В dev15 sources хранит сами неизменяемые Operation;
operation_references вычисляется из них. report_sources возвращает вклад тех же
версий в валюту/категорию/месяц, не перечитывая БД. Части/комиссии суммируются
по выбранным проводкам, полная сумма источника показывается отдельно. Названия
счетов и категорий взяты под тем же mutex. GUI показывает детали только для чтения.
Пустой отчёт не придумывает
валюту и месяцы. Названия категорий берутся согласованно с финансовым снимком.
Сохранения/экспорта отчёта пока нет, схема 0011 прежняя.

## Графики — dev16

Один read-only снимок используется таблицами, графиками и переходом к источникам.
Валюты не смешиваются. Месяцы показываются по 6, категории расходов по 8 на странице;
пустые месяцы не выдумываются. Возврат — отрицательный расход с точной подписью.
Размер столбца служит визуализации; исходные int, в том числе свыше int64 суммы
одного движения, сохраняются в снимке/подписях. Нет обратного преобразования
координат в финансовые факты. Масштаб страниц одной валюты/вида общий.
Щелчок открывает все операции месяца либо вклад выбранной категории. С клавиатуры
те же источники доступны из таблиц. Укороченное название графика не меняет полное
название в таблице/снимке. Экспорт/сеть/запись из графика отсутствуют.

## Backend общего OCR — dev17

OcrImporting.supports_universal true только для 0012, а supports_batches —
для 0011/0012. Проверка пары профиля/префикса одинакова при чтении и записи;
неизвестные профили и чужие префиксы отвергаются. _request отклоняет общий
профиль в старых схемах до записи, включая одиночный путь/пакет/повтор команды.
Канонический JSON версии 1 и хеши старого аудита не переписываются. Общий профиль
использует прежний Ledger, атомарные пакеты, закрытые периоды и защиту повторов.
То же изображение с другим OCR-контекстом — конфликт; новый DPI с тем же движением
даёт возможный повтор и требует выбора связи/отдельной операции.

## Общий финансовый GUI — dev18

После полного подтверждения backend MainWindow передаёт общий профиль в прежний
финансовый путь только при supports_universal. В 0012 карточка допускает подготовку,

## Фильтры аналитики — dev19

ReportScope содержит неизменяемые наборы UUID счетов/категорий: None означает
все, пустой frozenset — ничего. Банк преобразуется в набор его счетов по снимку
справочника; категория с потомками — в набор UUID. Счёт относится к источнику
дохода/расхода/возврата/комиссии, категория — к проводке части, а не всей операции.
Analytics.report(period, scope) читает текущий журнал под общим mutex, без записи.
Отчёт сохраняет scope и исходные версии; report_sources пересекает глобальный
отбор с выбранной строкой/месяцем/валютой. Сброс строки не расширяет scope.
Графики используют тот же отчёт. Выбранные имена — plain text, подсказка экранирована.

## Сравнение периодов — dev20

Analytics.compare получает оба периода и общий ReportScope. _snapshot читает
журнал ровно один раз под mutex/ensure_open. compare_periods формирует два отчёта
из одного tuple неизменяемых Operation и сравнивает доходы, расходы и разницу.
Категории/валюты объединяются; отсутствующая сторона имеет явный ноль с тем же
определением валюты. Разные определения одного кода валюты отвергаются.
Все изменения — int, второй минус первый. Проценты/нормирование не вычисляются.

IncomeExpenseComparison хранит оба исходных отчёта. GUI передаёт выбранный отчёт
в прежний IncomeExpenseDialog и выбирает валюту/категорию; нового чтения БД нет.
Отсутствующая сторона не подменяется другой валютой/категорией. В итогах переход
открывает валюту целиком, в категориях — выбранную категорию. Метрика дохода/расхода
в итогах не является дополнительным фильтром видов операций. Сброс вложенной
строки сохраняет общий scope. Схема 0012/финансовые команды/копии прежние.

## Доставка локального OCR — dev21

Общий bootstrap/ocr_runtime строит прежние CardRecognition для общего профиля,
Т-Банка и ВТБ из закреплённых хешей. Доверенный манифест берётся из ресурсов
приложения; runtime только по явному пути или рядом с frozen EXE. Проверка
ссылок/junction выполняется до разыменования, размеры ограничены, файлы хешируются
перед каждым распознаванием. Текст изображения/путь не попадает в JSON самопроверки.
Ошибка подключения не мешает обычной работе; скрытого поиска/скачивания нет.

В наборе 1243 проверки; стандартная source/EXE-самопроверка содержит 24 шага,
с реальным модулем — 26. Проверяются переносимость кириллического пути с пробелами,
автоматическое подключение в EXE, точные поля вымышленной карточки, пустая рабочая
папка и PATH без Python/uv. Стандартные CI выполняются без внешних OCR-бинарных
файлов. Лицензии всех DLL, чистая Windows и банковская точность остаются открыты.
[Доказательства и границы](stage-5-frozen-ocr-report.md). Схема 0012 не менялась.

## Явные формы валюты — dev22
