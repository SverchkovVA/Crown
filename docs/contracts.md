# Контракты

## Реализованные сценарии

- `create_vault(destination, name, password)` создаёт новую книгу и возвращает
  открытую сессию с отдельным кодом восстановления. Назначение не перезаписывается.
- `open_vault(root, credential, recovery=False)` проверяет формат, ключ, версию
  схемы, целостность и блокировку. Отсутствующий файл базы не создаётся.
- `Catalog.add_institution/add_account/add_category` валидируют ввод и передают
  команду адаптеру. Типизированные результаты не содержат ключей.
- `create_revision` сохраняет сущность, версию, группу, голову, журнал и квитанцию
  одной транзакцией. Тот же ID и тот же запрос возвращают прежний результат.
  Повтор ID с другим запросом вызывает ошибку.
- `VaultSession.check_integrity()` проверяет страницы, внешние ключи, принятые
  версии и наличие изменений в журнале.
- `Ledger.add(draft, command_id=None)` сохраняет полный сбалансированный набор
  проводок и возвращает Operation. Идентификатор команды необязателен для
  локального вызова; адаптер создаёт UUID, если он не передан.
- `Ledger.replace(id, expected_revision_id, draft, command_id=None)` создаёт
  новую версию только при совпадении принятого предшественника.
- `Ledger.delete(id, expected_revision_id, command_id=None)` сохраняет версию
  удаления. Предыдущие версии неизменяемы; удалённая операция не влияет на баланс.
- `Ledger.operations(include_deleted=False)`, `history(id)` и `balances(as_of=None)`
  читают принятые версии, полную линейную историю и остатки на конец даты.
  Без as_of баланс включает все даты; UI всегда передаёт выбранную дату.
- Один активный начальный остаток на счёт; он допускает ноль/отрицательное число.
  Движения не могут предшествовать его дате. Доход/расход/перевод/возврат положительны;
  комиссия перевода неотрицательна и требует расходную категорию при ненулевой сумме.
  Перевод требует разные счета одной валюты.
- Переполнение int64 любого остатка в конце любой финансовой даты отклоняет всю
  команду. Промежуточное сложение выполняется Python int, без SQLite SUM/float.
- Целостность включает хеши всех финансовых версий, точное совпадение проводок,
  ссылки и цепочки предшественников; порядок не зависит от часов устройства.
- `OperationDraft.parts` — tuple из 2–100 OperationPart для дохода/расхода/возврата:
  category_id отсутствует, категории уникальны, суммы положительны одной валюты
  и точно равны общей. Порядок частей сохраняется в версии/хеше. Пустой tuple
  сохраняет прежний контракт обычной операции. Переводы/остатки не разделяются.
- `Ledger.supports_splits` сообщает доступность разделения (схема 0004 и новее).
  Схема 0003 поддерживает обычный журнал; попытка записать части отклоняется
  без изменений и предлагает восстановить копию в новую папку.
- `Ledger.supports_refunds` сообщает доступность возвратов (0005).
- `Ledger.refund_candidates(excluding_refund_id=None)` возвращает активные
  покупки и доступные остатки по категориям, включая полностью возвращённые.
  При исправлении исключается собственная сумма действующего возврата.
- REFUND требует `refund_of` и `refund_of_revision_id` одной книги. Новый запрос
  требует текущую принятую версию неудалённого EXPENSE; устаревший просмотр
  отклоняется. Исторический снимок остаётся проверяемым после правок покупки.
  Дата не раньше покупки, валюта та же; счёт получения может отличаться.
- Проводки возврата уменьшают расходы на его дату. Совокупная сумма по каждой
  категории не превосходит текущий расход. Несовместимая правка/удаление покупки
  и превышение при конкурирующих командах отклоняются атомарно. Удаление возврата
  освобождает доступную сумму. Тот же идентификатор команды возвращает старый результат.
- `VaultSession.periods` доступен в 0006, в старых схемах равен None.
- `Periods.states()` возвращает состояния месяцев с историей; отсутствие месяца
  означает открытый период. `history(month)` возвращает цепочку от закрытия.
- `Periods.close(month, expected_revision_id=None, reason="", command_id=None)`
  закрывает месяц. Повторное закрытие ранее открытого требует ожидаемую версию.
- `Periods.reopen(month, expected_revision_id, reason=..., command_id=None)`
  явно открывает закрытый месяц, требует непустую причину. Состояния неизменяемы,
  повтор команды безопасен, устаревшая версия отклоняется.
- Все виды операций защищены по новому и прежнему месяцу, включая удаление,
  части, переводы, возвраты и изменение примечания. Просмотр/копии доступны;
  справочники не имеют финансовой даты и этим запретом не блокируются.
- Контроль удалённых изменений при будущей синхронизации ещё не реализован.
- `create_backup`, `verify_backup`, `restore_backup` описаны отдельно.

SQL-запросы параметризованы. Названия таблиц выбираются только из внутренних
констант. Пароли не принимаются через аргументы CLI и не попадают в SQL URL.

## Сохранённые будущие контракты

- OCR/CSV/OFX → ImportBatch → исправленные ImportItems → подтверждение ядром.
- Сверка показывает разницу, а не автоматически исправляет данные.
- Расчёт процентов принимает версии условий и фактические движения, возвращает
  график и предположения; не создаёт банковскую выплату.
- Прогноз принимает факты, планы и предположения, не создаёт фактические операции.
- QuoteProvider принимает только публичные идентификаторы инструментов.
  Количество бумаг, суммы и счета ему не передаются.
- RefreshPrices вызывается только кнопкой. PortfolioValuation читает локальные
  цены и никогда не инициирует сеть.
- Sync передаёт версии и атомарные группы с повторной доставкой и подтверждением
  после записи. Финансовые конфликты не разрешаются временем устройства.

Для Android общими будут схемы, денежные правила и контрольные примеры, а не
Python-объекты и не требование одинаковой физической схемы SQLite.
