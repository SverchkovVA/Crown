# ADR-0010: версионные правила категории и ручной приоритет

Статус: принято для проверочной dev9, часть 5.4.02 этапов 4–5; 27.10.2026.
Приёмка Windows и всего этапа остаётся отдельной.

1. Правило — локальная сущность category_rule с типизированной неизменяемой
   версией, общей историей, ожидаемым родителем, журналом и квитанцией.
   Выключение соответствует is_deleted, без физического удаления.
2. Условия ограничены видом дохода/расхода, буквальным текстом casefold и
   необязательным счётом. Категория совпадает по виду и книге. Больше приоритет —
   раньше; равный приоритет разных категорий требует ручного выбора.
3. Ручная категория/части главнее. Правила не меняют прошлые операции и не
   применяются к переводу/остатку/возврату. Нет сети, regex и обучения.
4. Правила и категории читаются одной SQL-транзакцией/RLock. В рабочем потоке
   готовятся решения для предпросмотра импорта. GUI показывает категорию/объяснение;
   ручная правка не переопределяется. Прежний Importing.confirm сохраняет факты
   только после явного подтверждения и повторной проверки денежных инвариантов.
5. Новая схема 0009, старые книги читаются без миграции на месте. Переход через
   проверенную копию и новую папку. При batch-пересоздании entities сохраняются
   определения всех старых триггеров; расширяется только выбор типизированного
   payload. DDL и возврат защит выполняются одной транзакцией; сбой откатывается.
6. Правила входят в зашифрованную копию с историей. Новая локальная реплика не
   меняет их смысл. Финансовые хеши, форматы ключей/копий и стек не меняются.
7. Проверки охватывают атомарность/аварию процесса, конкуренцию, старые защиты,
   неизменность исходной 0008, историю копии, GUI и самопроверку EXE (17 шагов).
   Банк/OCR-адаптеры и точность реальных изображений этим не подтверждаются.
