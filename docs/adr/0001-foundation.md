# ADR-0001: основа этапа 3

Дата: 25.10.2026. Архитектура и детальное проектирование утверждены пользователем.

## Решения

1. Python 3.13.16, PySide6 Essentials 6.12.0, SQLAlchemy 2.1.6, Alembic 1.20.1,
   sqlcipher3 0.6.4 и PyNaCl 1.6.2. Полный граф с хешами — uv.lock.
2. Essentials содержит необходимые Core/Gui/Widgets без установки всех Qt Addons.
   Графики будут добавлены с аналитикой через Matplotlib. OCR-зависимости не
   устанавливаются до проверки финансового ядра.
3. Использован sqlcipher3 от основного проекта coleifer: доступны wheels Windows
   x64 и Linux. Fork sqlcipher3-wheels и обычный sqlite3 не используются.
4. SQLAlchemy Core выбран для неизменяемых справочников; порт отделяет SQL от
   сценариев. Дублирующих доменных ORM-моделей нет.
5. Книга — каталог с единой публикуемой подпапкой data. База и обёртка ключа
   появляются вместе. Существующее назначение никогда не заменяется.
6. Случайный ключ базы, обёртки паролем и независимым кодом восстановления.
   Потоковая копия получает отдельный пароль и содержит материал восстановления
   только внутри аутентифицированного шифрования.
7. История версий и журнал вводятся сейчас; проводки и сетевой протокол — позже.
8. Миграции устанавливают только новую схему; несовместимые старые/новые версии
   отклоняются. До первого пользовательского обновления нужен проверенный путь
   миграции через резервированную рабочую копию.
9. Этап 3 не включает этап 4: нет скрытой реализации неподтверждённого финансового
   журнала и нет перехода к OCR.

## Последствия

Основа тестируется без финансовых данных. Наличие wheels и Linux-тесты ещё не
доказывают работоспособность Windows 11. Workflow, spec и самопроверка помогают
выполнить эту проверку, но не заменяют её результат.
