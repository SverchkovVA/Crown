# ADR-0002: первая поставка журнала и обновление только копии

Дата: 26.10.2026. Пользователь разрешил следующие этапы. Дополняет ADR-0001:
пункты 7–9 описывали границы этапа 3, а не запрет разрешённого впоследствии этапа 4.

## Решения

1. Сохранить модульный монолит и SQLAlchemy Core. Доменный OperationDraft
   формирует точные сбалансированные проводки; SQL-адаптер публикует их вместе
   с версией/группой/журналом/квитанцией в одной транзакции.
2. Исправление требует ожидаемого принятого предшественника. Прежние версии
   неизменяемы. Удаление сохраняет tombstone; только текущие активные версии
   влияют на остатки. Цепочка родителей определяет историю независимо от часов.
3. Финансовая дата — календарный день. Остаток на дату включает все движения
   по этот день. Проверять int64 для каждого счёта в конце каждой даты,
   включая прошлые дни после исправления. Промежуточные суммы — Python int.
4. В новой схеме 0003 доступны журнал/проводки. Старая 0002 открывается без
   миграции исходной книги, со справочниками и резервированием. Это обеспечивает
   сохранность исходного состояния и возможность продолжить работу в 0.1.2.
5. Переход 0002 → 0003 выполняется только внутри восстановления проверенной
   зашифрованной копии в новую папку. Сначала проверить старую промежуточную
   базу, транзакционно обновить её, проверить связи/историю и создать новую
   реплику/обёртку ключа. При ошибке не публиковать папку назначения.
   Понижение и перезапись не поддерживаются; ключи и контейнер остаются v1.
6. GUI явно освобождает главное окно до глобальной очистки QApplication.
   Самопроверка не оставляет скрытое главное окно на завершение интерпретатора.
   Поддержка доступности Qt сохраняется.

## Последствия

Обновление старой книги требует явной копии/восстановления и нового PF1.
Книги 0003 не читаются приложением 0.1.2. Журнал содержит только базовые ручные
операции; split и согласованные расширения не считаются готовыми. Приёмка
этапа 3 и ручная проверка новой поставки остаются отдельными задачами.
Фактические доказательства: docs/stage-3-report.md и docs/stage-4-report.md.
