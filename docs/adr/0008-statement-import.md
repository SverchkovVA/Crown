# ADR-0008: локальный CSV/OFX и атомарное подтверждение выписки

Статус: принято для разрешённого расширения A2 этапа 4, 27.10.2026.

1. Файл читается локально по явному выбору. До подтверждения ImportDocument,
   ошибки и исправленные ImportSelection находятся только в памяти. В книге
   сохраняется нормализованный аудит выбранных строк, не полный файл/путь.
2. Общий CSV: заголовок, дата, одна сумма со знаком, необязательные описание,
   внешний ID и RUB. Явно выбираются кодировка, разделитель и два формата даты.
   Точные суммы разбираются без float/округления. Произвольные банковские макеты
   не объявляются поддержанными без образцов и проверки.
3. OFX ограничен проведёнными STMTTRN одного банковского/карточного RUB-счёта,
   1.x SGML и 2.x XML. Берётся календарная дата DTPOSTED, без пересчёта по ОС.
   По спецификации FITID нужен для повторных выгрузок, знак TRNAMT задаёт движение;
   STMTTRNP не является проведённым фактом. Банковские корректировки/дополнительные
   валюты требуют отдельной ручной проверки, отображаются исключёнными ошибками.
   [Первичный источник: OFX Banking 2.3, 3.2.3, 11.4.4](https://financialdataexchange.org/wp-content/uploads/2025/12/OFX-Banking-Specification-v2.3.pdf).
4. Размер до 8 МиБ/2000 строк; поле, глубина и число узлов ограничены. DTD и
   ENTITY запрещены. Парсер не загружает внешние данные, изображения или ссылки.
   Ошибки показываются без финансового содержимого в диагностике.
5. Ключ повтора включает счёт книги, формат/область источника и внешний ID;
   без ID — SHA-256 файла/номер строки. Разные сведения одного известного ID
   блокируются. Совпадение даты/суммы не доказывает повтор: нужна явная связь
   либо подтверждение отдельной операции. Без ID другая выгрузка требует решения.
6. Строка исправляется общей формой операции: дата, сумма, категории/части,
   перевод, возврат и теги. Сохраняются RUB и направление движения выбранного
   счёта, начальные остатки исключены. Источник остаётся отдельным снимком.
   Связь требует текущую ожидаемую версию, точную исходную дату/движение и не
   создаёт финансовой версии. Обе стороны выписки могут ссылаться на один перевод.
7. Подтверждение повторно проверяет всё под RLock в одной транзакции. Новые версии,
   проводки, аудит, головы, журнал и квитанции записываются атомарно. Все новые
   версии имеют общую change_group. Дневные остатки проверяются после всех строк,
   поэтому временное промежуточное превышение внутри незавершённой группы не
   запрещает допустимый итог дня; конечное переполнение откатывает всю группу.
8. Повтор команды возвращает исходные версии даже после последующих правок.
   Копия/новая реплика сохраняют ключи повтора. Закрытые периоды защищают новые
   операции; связь с существующей операцией не меняет финансовые факты месяца.
9. Схема 0008 добавляет только таблицы/защиту аудита; миграции 0001–0007 и старые
   финансовые хеши не меняются. Старые книги читаются без обновления; миграция
   только проверенной копии в новую папку. Форматы ключей/копий и библиотеки прежние.
   Аудит пока локален: наличие группы не означает реализованную синхронизацию.

Доказательства и ограничения: [отчёт импорта](../stage-4-import-report.md).
